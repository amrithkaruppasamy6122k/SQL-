Chapter 23: Union and Union ALL

Multiple Query Results Ah Combine Panni Oru Single Result Set Panalam!

📖 Definition (Union Enna Machan?)

UNION na rendu yaa athiga SELECT queries oda results ah onu combine panni single result set aakki return panra operation thaan. Idhu vertical ah data combine pannum (rows add aagum, columns increase aagadhu).

Union operations oda mukkiya features:

  • Multiple queries combine: Rendu yaa athiga SELECT statements oda results onu aakkalam
  • Same structure venum: Ellam queries layum same number of columns irukanum
  • Data type compatible: Corresponding columns oda data types match aaganum
  • Duplicate handling: UNION duplicate rows remove pannum, UNION ALL ellam rows keep pannum
  • Vertical combination: Rows add aagum (horizontal ah illa)

🎯 Union Basic Syntax:

SELECT columns FROM table1 UNION SELECT columns FROM table2;

Rendu SELECT statements layum same number of columns irukanum!

🔄 UNION vs UNION ALL Difference:

  • UNION: Duplicate rows automatic ah remove pannum (slower but clean result)
  • UNION ALL: Ellam rows as-is ah keep pannum (faster but duplicates irukalam)

⚠️ Jaakkirathaya Kavanikanum:

  • Column count mismatch aana error varum
  • Data type incompatible aana implicit conversion try pannum
  • Performance ku UNION ALL better (sorting/deduplication illa)
  • ORDER BY last query ku after mattum use panalam
  • Column names first SELECT statement la irundhu edukum

🏛️ Standard (Union Types aur Avanga Velai)

MySQL la different types oda union operations use panna mudiyum:

Operation Type Tamil la Explanation Performance Duplicates
UNION Duplicate rows remove panni clean result kudukum Slow (sorting required) Removed
UNION ALL Ellam rows as-is ah combine pannum Fast (no sorting) Preserved
UNION DISTINCT Same as UNION (explicit duplicate removal) Slow Removed

📍 Union Requirements:

  • Column count: Ellam SELECT statements layum same number of columns irukanum
  • Data type compatibility: Corresponding positions la similar data types venum
  • Column names: First SELECT oda column names use aagum final result la
  • ORDER BY placement: Final result ku mattum use panalam (individual queries la illa)

📊 Performance Comparison:

UNION ALL use panunga when:

  • Duplicate rows problem illa nu therinja
  • Performance critical applications la
  • Large datasets combine pannum bodhu

UNION use panunga when:

  • Clean, unique results venum
  • Data quality important
  • Small to medium datasets la

🎯 Examples with Full Tamil Explanation

1. Basic UNION - Duplicate rows remove panna

SELECT customer_name, contact_number, 'Premium' AS customer_type FROM premium_customers UNION SELECT customer_name, contact_number, 'Regular' AS customer_type FROM regular_customers ORDER BY customer_name;
Line-by-line Tamil Explanation:
• SELECT customer_name, contact_number, 'Premium' AS customer_type - Premium customers details select panrom
• FROM premium_customers - premium_customers table la irundhu data edukrom
• UNION - First query result oda second query result combine panrom, duplicates remove aagum
• SELECT customer_name, contact_number, 'Regular' AS customer_type - Regular customers details select panrom
• FROM regular_customers - regular_customers table data
• ORDER BY customer_name - Final combined result ah customer name wise sort panrom
• Result: Rendu type customers um oru list la varum, duplicates automatically remove aagidum

2. UNION ALL - Ellam rows keep panradhu

SELECT transaction_date, amount, 'Income' AS transaction_type, description FROM income_transactions WHERE transaction_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) UNION ALL SELECT transaction_date, amount, 'Expense' AS transaction_type, description FROM expense_transactions WHERE transaction_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) ORDER BY transaction_date DESC;
Line-by-line Tamil Explanation:
• SELECT transaction_date, amount, 'Income' AS transaction_type, description - Income transaction details select panrom
• FROM income_transactions - income_transactions table data
• WHERE transaction_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) - Last 30 days income transactions filter
• UNION ALL - Income aur expense results combine panrom, duplicates preserve aagum
• SELECT transaction_date, amount, 'Expense' AS transaction_type, description - Expense transaction details select panrom
• FROM expense_transactions - expense_transactions table data
• WHERE transaction_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) - Last 30 days expense transactions filter
• ORDER BY transaction_date DESC - Combined result ah latest date first order la sort panrom
• Usage: Complete financial transaction history paakradhu ku perfect

3. Multiple UNION - Moonu table ah combine panradhu

SELECT employee_id, employee_name, 'Current' AS employment_status, hire_date AS status_date FROM current_employees WHERE department_id = 101 UNION SELECT employee_id, employee_name, 'Former' AS employment_status, termination_date AS status_date FROM former_employees WHERE department_id = 101 UNION SELECT employee_id, employee_name, 'Contract' AS employment_status, contract_start_date AS status_date FROM contract_employees WHERE department_id = 101 ORDER BY employment_status, employee_name;
Line-by-line Tamil Explanation:
• SELECT employee_id, employee_name, 'Current' AS employment_status, hire_date AS status_date - Current employees data with status label
• FROM current_employees WHERE department_id = 101 - Department 101 current employees filter
• UNION - First query result oda second query combine panrom
• SELECT employee_id, employee_name, 'Former' AS employment_status, termination_date AS status_date - Former employees data with different status
• FROM former_employees WHERE department_id = 101 - Same department former employees
• UNION - Second UNION for third table combination
• SELECT employee_id, employee_name, 'Contract' AS employment_status, contract_start_date AS status_date - Contract employees data
• FROM contract_employees WHERE department_id = 101 - Contract employees from same department
• ORDER BY employment_status, employee_name - Employment type first, then name wise sort
• Result: Department oda complete employee history (current + former + contract) oru list la varum

4. UNION with Different Column Names - Column aliasing

SELECT product_name AS item_name, selling_price AS item_price, 'Product' AS item_category, stock_quantity AS available_quantity FROM products WHERE status = 'ACTIVE' UNION ALL SELECT service_name AS item_name, service_charge AS item_price, 'Service' AS item_category, NULL AS available_quantity FROM services WHERE status = 'ACTIVE' ORDER BY item_category, item_price DESC;
Line-by-line Tamil Explanation:
• SELECT product_name AS item_name, selling_price AS item_price - Product details ah common names la alias panrom
• 'Product' AS item_category, stock_quantity AS available_quantity - Category label aur stock info select panrom
• FROM products WHERE status = 'ACTIVE' - Active products mattum filter
• UNION ALL - Products aur services combine panrom, performance ku ALL use panrom
• SELECT service_name AS item_name, service_charge AS item_price - Service details ah same alias names la select panrom
• 'Service' AS item_category, NULL AS available_quantity - Services ku stock illa so NULL assign panrom
• FROM services WHERE status = 'ACTIVE' - Active services filter
• ORDER BY item_category, item_price DESC - Category first, price high to low sort
• Key Point: Different table columns ah common names la alias panni combine panalam

5. UNION with Calculations - Calculated fields combine panradhu

SELECT 'Q1' AS quarter, SUM(revenue) AS total_revenue, COUNT(*) AS total_transactions, AVG(revenue) AS avg_transaction_value FROM sales_q1_2024 UNION ALL SELECT 'Q2' AS quarter, SUM(revenue) AS total_revenue, COUNT(*) AS total_transactions, AVG(revenue) AS avg_transaction_value FROM sales_q2_2024 UNION ALL SELECT 'Q3' AS quarter, SUM(revenue) AS total_revenue, COUNT(*) AS total_transactions, AVG(revenue) AS avg_transaction_value FROM sales_q3_2024 UNION ALL SELECT 'Q4' AS quarter, SUM(revenue) AS total_revenue, COUNT(*) AS total_transactions, AVG(revenue) AS avg_transaction_value FROM sales_q4_2024 ORDER BY quarter;
Line-by-line Tamil Explanation:
• SELECT 'Q1' AS quarter, SUM(revenue) AS total_revenue - Q1 quarter label oda total revenue calculate panrom
• COUNT(*) AS total_transactions, AVG(revenue) AS avg_transaction_value - Transaction count aur average value calculate panrom
• FROM sales_q1_2024 - Q1 sales data table
• UNION ALL - Q1 aur Q2 results combine panrom (duplicates possible illa so ALL use panrom)
• SELECT 'Q2' AS quarter - Q2 quarter ku same calculations
• FROM sales_q2_2024 - Q2 sales data
• UNION ALL SELECT 'Q3' AS quarter... FROM sales_q3_2024 - Q3 data combine
• UNION ALL SELECT 'Q4' AS quarter... FROM sales_q4_2024 - Q4 data combine
• ORDER BY quarter - Quarter wise sort (Q1, Q2, Q3, Q4 order la varum)
• Usage: Quarterly performance comparison panradhu ku excellent technique

🛠️ Use Cases (Real-world la Epidi Use Pannalam)

1. E-commerce - Complete Product Catalog

Situation: Different categories la irukra products ellam oru master list la combine pannanum

SELECT product_name, price, 'Electronics' AS category, brand, warranty_period AS special_attribute FROM electronics_products WHERE status = 'AVAILABLE' UNION ALL SELECT product_name, price, 'Clothing' AS category, brand, size AS special_attribute FROM clothing_products WHERE status = 'AVAILABLE' UNION ALL SELECT product_name, price, 'Books' AS category, author AS brand, isbn AS special_attribute FROM books WHERE status = 'AVAILABLE' ORDER BY category, price;

Faayda: Search functionality ku single query la ellam products access panalam, inventory management easy aagum

2. HR Management - Complete Employee Directory

Situation: Full-time, part-time, contract employees ellam oru directory la venum

SELECT employee_name, employee_id, department_name, 'Full-Time' AS employment_type, salary AS compensation, hire_date AS start_date FROM full_time_employees WHERE status = 'ACTIVE' UNION ALL SELECT employee_name, employee_id, department_name, 'Part-Time' AS employment_type, hourly_rate * 20 AS compensation, hire_date AS start_date FROM part_time_employees WHERE status = 'ACTIVE' UNION ALL SELECT contractor_name AS employee_name, contract_id AS employee_id, project_department AS department_name, 'Contract' AS employment_type, monthly_payment AS compensation, contract_start_date AS start_date FROM contractors WHERE contract_status = 'ACTIVE' ORDER BY department_name, employment_type, employee_name;

Faayda: HR team ku complete workforce overview kidaikum, resource planning aur communication easy aagum

3. Financial Reporting - Complete Transaction History

Situation: Bank account la ellam types oda transactions onu combine panni statement generate pannanum

SELECT transaction_date, transaction_id, 'Deposit' AS transaction_type, amount, depositor_name AS party_name, branch_name AS location FROM deposits WHERE account_number = 'ACC123456' AND transaction_date >= DATE_SUB(CURDATE(), INTERVAL 6 MONTH) UNION ALL SELECT transaction_date, transaction_id, 'Withdrawal' AS transaction_type, -amount AS amount, beneficiary_name AS party_name, atm_location AS location FROM withdrawals WHERE account_number = 'ACC123456' AND transaction_date >= DATE_SUB(CURDATE(), INTERVAL 6 MONTH) UNION ALL SELECT transfer_date AS transaction_date, transfer_id AS transaction_id, 'Transfer Out' AS transaction_type, -transfer_amount AS amount, recipient_name AS party_name, 'Online' AS location FROM money_transfers WHERE sender_account = 'ACC123456' AND transfer_date >= DATE_SUB(CURDATE(), INTERVAL 6 MONTH) ORDER BY transaction_date DESC, transaction_id;

Faayda: Customer ku complete account statement kidaikum, financial tracking easy aagum

4. Healthcare - Patient Medical Records Integration

Situation: Different systems la irukra patient data ellam onu combine panni complete medical history create pannanum

SELECT patient_id, record_date, 'Consultation' AS record_type, doctor_name AS healthcare_provider, diagnosis AS record_details, consultation_fee AS cost FROM consultation_records WHERE patient_id = 'PAT001' AND record_date >= DATE_SUB(CURDATE(), INTERVAL 1 YEAR) UNION ALL SELECT patient_id, test_date AS record_date, 'Lab Test' AS record_type, lab_technician AS healthcare_provider, test_results AS record_details, test_cost AS cost FROM lab_tests WHERE patient_id = 'PAT001' AND test_date >= DATE_SUB(CURDATE(), INTERVAL 1 YEAR) UNION ALL SELECT patient_id, prescription_date AS record_date, 'Prescription' AS record_type, prescribing_doctor AS healthcare_provider, medicine_details AS record_details, medicine_cost AS cost FROM prescriptions WHERE patient_id = 'PAT001' AND prescription_date >= DATE_SUB(CURDATE(), INTERVAL 1 YEAR) ORDER BY record_date DESC;

Faayda: Doctor ku patient oda complete medical timeline theriyum, better treatment decisions eduka mudiyum

5. Educational Management - Student Academic History

Situation: Student oda ellam semesters marks, attendance, activities ellam onu combine panni academic profile create pannanum

SELECT student_id, semester_name AS academic_period, 'Academic Performance' AS record_category, CONCAT('GPA: ', gpa) AS performance_metric, total_credits AS credits_hours, semester_end_date AS record_date FROM semester_results WHERE student_id = 'STU2024001' UNION ALL SELECT student_id, activity_period AS academic_period, 'Extra Curricular' AS record_category, activity_name AS performance_metric, activity_hours AS credits_hours, activity_end_date AS record_date FROM student_activities WHERE student_id = 'STU2024001' UNION ALL SELECT student_id, CONCAT(academic_year, ' - ', semester) AS academic_period, 'Attendance Record' AS record_category, CONCAT('Attendance: ', attendance_percentage, '%') AS performance_metric, total_classes AS credits_hours, semester_end_date AS record_date FROM attendance_records WHERE student_id = 'STU2024001' ORDER BY record_date DESC, record_category;

Faayda: Academic advisor ku student oda complete academic journey theriyum, proper guidance provide panna mudiyum
