Chapter 14: Aggregation Functions Complete Guide

📖 Definition

Aggregation Functions: Aggregation functions use panni multiple rows-la irukura data-va single result-a convert pannalam. Example: 100 students-oda marks irundha, average marks kandu pudikalam, total students count pannalam, highest marks find pannalam. Data analysis and reporting-ku aggregation functions romba important.

🎯 Main Aggregation Functions

📊 COUNT

Records Count panradhu

COUNT(*) | COUNT(column)

Total number of rows or non-null values

➕ SUM

Total Add panradhu

SUM(column)

Add all numeric values in a column

📈 AVG

Average Calculate panradhu

AVG(column)

Mathematical average of numeric values

🔍 MIN/MAX

Smallest/Largest Value

MIN(column) | MAX(column)

Find minimum or maximum value

📊 COUNT Function

-- Basic COUNT examples -- Count total number of sales records SELECT COUNT(*) AS total_sales FROM sales_data; -- Count non-null sales_person entries SELECT COUNT(sales_person) AS sales_with_person FROM sales_data; -- Count distinct categories SELECT COUNT(DISTINCT category) AS unique_categories FROM sales_data; -- Count sales by category SELECT category, COUNT(*) AS sales_count FROM sales_data GROUP BY category ORDER BY sales_count DESC;
COUNT Function Explanation:
COUNT(*) - Total rows count pannum, NULL values um include aagum
COUNT(sales_person) - NULL illa-na entries mattum count pannum
COUNT(DISTINCT category) - Unique categories mattum count pannum
GROUP BY category - Each category-ku separate count kudukum

➕ SUM Function

-- Basic SUM examples -- Total revenue from all sales SELECT SUM(sale_amount) AS total_revenue FROM sales_data; -- Total quantity sold SELECT SUM(quantity_sold) AS total_quantity FROM sales_data; -- Revenue by category SELECT category, SUM(sale_amount) AS category_revenue, SUM(quantity_sold) AS category_quantity FROM sales_data GROUP BY category ORDER BY category_revenue DESC; -- Revenue by region with formatting SELECT region, SUM(sale_amount) AS total_revenue, CONCAT('₹', FORMAT(SUM(sale_amount), 2)) AS formatted_revenue FROM sales_data GROUP BY region ORDER BY total_revenue DESC;

SUM(sale_amount) - All sale amounts add panni total revenue calculate pannum
SUM(quantity_sold) - Total products sold quantity sum pannum
GROUP BY category - Each category-ku separate sum calculate pannum

📈 AVG (Average) Function

-- Basic AVG examples -- Average sale amount SELECT AVG(sale_amount) AS average_sale_amount, ROUND(AVG(sale_amount), 2) AS rounded_average FROM sales_data; -- Average quantity per sale SELECT AVG(quantity_sold) AS avg_quantity_per_sale FROM sales_data; -- Average sale amount by category SELECT category, COUNT(*) AS total_sales, AVG(sale_amount) AS avg_amount, ROUND(AVG(sale_amount), 2) AS rounded_avg FROM sales_data GROUP BY category ORDER BY avg_amount DESC; -- Compare individual sales with category average SELECT product_name, category, sale_amount, ROUND(AVG(sale_amount) OVER (PARTITION BY category), 2) AS category_avg, CASE WHEN sale_amount > AVG(sale_amount) OVER (PARTITION BY category) THEN 'Above Average' ELSE 'Below Average' END AS performance FROM sales_data ORDER BY category, sale_amount DESC;
AVG Function Explanation:
AVG(sale_amount) - All sale amounts-oda mathematical average calculate pannum
ROUND(AVG(amount), 2) - Average-a 2 decimal places-ku round pannum
AVG() OVER (PARTITION BY category) - Window function use panni each category average calculate pannum
CASE WHEN with AVG - Average-oda compare panni condition check pannum

🔍 MIN and MAX Functions

-- Basic MIN and MAX examples -- Find highest and lowest sale amounts SELECT MIN(sale_amount) AS lowest_sale, MAX(sale_amount) AS highest_sale, MAX(sale_amount) - MIN(sale_amount) AS sale_range FROM sales_data; -- Find earliest and latest sale dates SELECT MIN(sale_date) AS first_sale_date, MAX(sale_date) AS last_sale_date, DATEDIFF(MAX(sale_date), MIN(sale_date)) AS sales_period_days FROM sales_data; -- MIN and MAX by category SELECT category, MIN(sale_amount) AS min_sale, MAX(sale_amount) AS max_sale, AVG(sale_amount) AS avg_sale, COUNT(*) AS total_sales FROM sales_data GROUP BY category ORDER BY max_sale DESC; -- Find products with highest and lowest sales SELECT product_name, category, sale_amount, 'Highest Sale' AS sale_type FROM sales_data WHERE sale_amount = (SELECT MAX(sale_amount) FROM sales_data) UNION ALL SELECT product_name, category, sale_amount, 'Lowest Sale' AS sale_type FROM sales_data WHERE sale_amount = (SELECT MIN(sale_amount) FROM sales_data) ORDER BY sale_amount DESC;
MIN/MAX Function Explanation:
MIN(sale_amount) - Column-la irukura smallest value return pannum
MAX(sale_amount) - Column-la irukura largest value return pannum
MAX() - MIN() - Range calculate panna use pannalam
DATEDIFF(MAX(date), MIN(date)) - Date range days-la calculate pannum
Subquery with MIN/MAX - Specific records find panna use pannalam

🔀 Advanced Aggregation Combinations

-- Complex aggregation with multiple functions SELECT region, COUNT(*) AS total_sales, SUM(sale_amount) AS total_revenue, AVG(sale_amount) AS avg_sale, MIN(sale_amount) AS min_sale, MAX(sale_amount) AS max_sale, SUM(quantity_sold) AS total_quantity, ROUND(SUM(sale_amount) / SUM(quantity_sold), 2) AS avg_price_per_unit FROM sales_data GROUP BY region ORDER BY total_revenue DESC; -- Sales performance analysis SELECT sales_person, COUNT(*) AS sales_count, SUM(sale_amount) AS total_sales, ROUND(AVG(sale_amount), 2) AS avg_sale_amount, MAX(sale_amount) AS best_sale, ROUND(SUM(sale_amount) / COUNT(*), 2) AS performance_ratio FROM sales_data WHERE sales_person IS NOT NULL GROUP BY sales_person HAVING COUNT(*) >= 2 -- Only persons with 2+ sales ORDER BY total_sales DESC; -- Monthly aggregation (if we had monthly data) SELECT YEAR(sale_date) AS sale_year, MONTH(sale_date) AS sale_month, MONTHNAME(sale_date) AS month_name, COUNT(*) AS monthly_sales_count, SUM(sale_amount) AS monthly_revenue, ROUND(AVG(sale_amount), 2) AS monthly_avg_sale FROM sales_data GROUP BY YEAR(sale_date), MONTH(sale_date) ORDER BY sale_year, sale_month;

📊 Aggregation with Conditional Logic

-- Conditional aggregation using CASE SELECT category, COUNT(*) AS total_sales, SUM(CASE WHEN sale_amount >= 10000 THEN 1 ELSE 0 END) AS high_value_sales, SUM(CASE WHEN sale_amount < 5000 THEN 1 ELSE 0 END) AS low_value_sales, ROUND( (SUM(CASE WHEN sale_amount >= 10000 THEN 1 ELSE 0 END) * 100.0) / COUNT(*), 2 ) AS high_value_percentage FROM sales_data GROUP BY category; -- Revenue analysis with conditional sums SELECT region, SUM(sale_amount) AS total_revenue, SUM(CASE WHEN category = 'Electronics' THEN sale_amount ELSE 0 END) AS electronics_revenue, SUM(CASE WHEN category = 'Clothing' THEN sale_amount ELSE 0 END) AS clothing_revenue, SUM(CASE WHEN category = 'Books' THEN sale_amount ELSE 0 END) AS books_revenue FROM sales_data GROUP BY region ORDER BY total_revenue DESC;

🔧 Use Cases

1. E-commerce Dashboard

Scenario: Management-ku daily sales summary venum
SELECT DATE(sale_date) AS sale_date, COUNT(*) AS total_orders, SUM(sale_amount) AS daily_revenue, AVG(sale_amount) AS avg_order_value, MAX(sale_amount) AS highest_order FROM sales_data GROUP BY DATE(sale_date) ORDER BY sale_date DESC;

2. Inventory Management

Scenario: Product categories performance analysis
SELECT category, COUNT(DISTINCT product_name) AS unique_products, SUM(quantity_sold) AS total_units_sold, AVG(quantity_sold) AS avg_units_per_sale, SUM(sale_amount) / SUM(quantity_sold) AS avg_price_per_unit FROM sales_data GROUP BY category;

3. Sales Team Performance

Scenario: Sales person rankings and targets
SELECT sales_person, COUNT(*) AS sales_made, SUM(sale_amount) AS total_revenue, ROUND(AVG(sale_amount), 2) AS avg_sale_value, CASE WHEN SUM(sale_amount) >= 20000 THEN 'Excellent' WHEN SUM(sale_amount) >= 10000 THEN 'Good' ELSE 'Needs Improvement' END AS performance_rating FROM sales_data WHERE sales_person IS NOT NULL GROUP BY sales_person ORDER BY total_revenue DESC;

4. Financial Reporting

Scenario: Regional revenue comparison
SELECT region, SUM(sale_amount) AS region_revenue, ROUND( (SUM(sale_amount) * 100.0) / (SELECT SUM(sale_amount) FROM sales_data), 2 ) AS revenue_percentage, RANK() OVER (ORDER BY SUM(sale_amount) DESC) AS revenue_rank FROM sales_data GROUP BY region;

⚠️ Common Mistakes & Best Practices

Common Mistakes to Avoid:

❌ NULL Values: SUM, AVG, MIN, MAX functions NULL values ignore pannum - data accuracy check pannunga
❌ Wrong GROUP BY: Non-aggregate columns GROUP BY-la mention pannama irunga
❌ COUNT vs COUNT(*): COUNT(column) NULL values count panna, COUNT(*) all rows count pannum
❌ Division by Zero: AVG calculation-la zero values check pannunga
❌ Data Types: Text columns-la SUM use pannakoodadhu

Best Practices:

✅ Use ROUND(): Decimal results-a appropriate precision-ku round pannunga
✅ Handle NULLs: COALESCE() or IFNULL() use panni NULL values handle pannunga
✅ Use HAVING: Aggregated results filter panna HAVING clause use pannunga
✅ Meaningful Aliases: Result columns-ku descriptive names kudunga
✅ Test with Sample Data: Large datasets-ku munadi small data-la test pannunga

📊 Performance Tips

Optimization Techniques:

⚡ Indexes: GROUP BY columns-ku index create pannunga
⚡ WHERE First: GROUP BY-ku munadi WHERE clause use panni data reduce pannunga
⚡ LIMIT Results: Top N results-ku mattum LIMIT use pannunga
⚡ Avoid SELECT *: Required columns mattum select pannunga
⚡ Use EXPLAIN: Query execution plan analyze pannunga

📚 Quick Reference

  • COUNT(*): Total rows count (including NULL)
  • COUNT(column): Non-NULL values count
  • SUM(column): Add all numeric values
  • AVG(column): Mathematical average
  • MIN/MAX(column): Smallest/Largest value
  • GROUP BY: Aggregate by categories
  • HAVING: Filter aggregated results
  • ROUND(value, 2): Round to 2 decimal places
