📖 Definition (Views enna?)

View na oru virtual table thaan. Idhu physically database la store agadhu, but oru SELECT query oda result ah table maari show pannum.

Views oda main features:

  • Data security and privacy maintain panalam
  • Complex queries ah simplify panalam
  • User access control implement panalam
  • Data abstraction layer create panalam
  • Reusable query definitions store panalam

🎯 View Basic Structure:

CREATE VIEW view_name AS SELECT query;

View use pannum bodhu normal table maari thaan query panalam!

⚠️ Important Points:

  • View la data physically store aagadhu
  • Underlying table data change aanalum view la reflect agum
  • Complex views la INSERT, UPDATE, DELETE panradhu limitations irukum

🏛️ Standard (Views Types & Operations)

MySQL la views ah different types la classify panalam:

View Type Description Updatable
Simple View Single table la irundhu create pandra view Yes (with conditions)
Complex View Multiple tables, functions, GROUP BY use pandra view No
Materialized View Result ah physically store pandra view (MySQL la direct support illa) Depends on implementation
Updatable View INSERT, UPDATE, DELETE operations allow pandra view Yes
Read-Only View Only SELECT operations allow pandra view No

📍 View Operations:

  • CREATE VIEW: New view create panna
  • ALTER VIEW: Existing view modify panna
  • DROP VIEW: View delete panna
  • SHOW CREATE VIEW: View definition show panna
  • DESCRIBE VIEW: View structure show panna

🎯 Examples with Detailed Explanation

1. Simple View Creation - Employee basic details view

CREATE VIEW employee_basic_info AS SELECT employee_id, employee_name, department_id, hire_date FROM employees WHERE status = 'ACTIVE';
Line-by-line explanation:
• CREATE VIEW employee_basic_info AS - 'employee_basic_info' name la view create panrom
• SELECT employee_id, employee_name, department_id, hire_date - Basic employee details select panrom
• FROM employees - employees table la irundhu data get panrom
• WHERE status = 'ACTIVE' - Active employees ah mattum filter panrom
• Usage: SELECT * FROM employee_basic_info; - Normal table maari use panalam

2. Complex View with JOIN - Employee department details view

CREATE VIEW employee_department_info AS SELECT e.employee_name, e.salary, d.department_name, d.location FROM employees e JOIN departments d ON e.department_id = d.department_id WHERE e.status = 'ACTIVE';
Line-by-line explanation:
• CREATE VIEW employee_department_info AS - Complex view create panrom
• SELECT e.employee_name, e.salary, d.department_name, d.location - Employee and department details combine panrom
• FROM employees e - employees table ku 'e' alias
• JOIN departments d ON e.department_id = d.department_id - departments table oda join panrom
• WHERE e.status = 'ACTIVE' - Active employees filter
• Note: Idhu complex view, so direct ah update panna mudiyathu

3. View with Aggregate Functions - Department statistics view

CREATE VIEW department_statistics AS SELECT d.department_name, COUNT(e.employee_id) AS total_employees, AVG(e.salary) AS average_salary, MAX(e.salary) AS highest_salary, MIN(e.salary) AS lowest_salary FROM departments d LEFT JOIN employees e ON d.department_id = e.department_id WHERE e.status = 'ACTIVE' OR e.status IS NULL GROUP BY d.department_id, d.department_name;
Line-by-line explanation:
• CREATE VIEW department_statistics AS - Statistics view create panrom
• SELECT d.department_name, COUNT(e.employee_id) AS total_employees - Department name and employee count
• AVG(e.salary) AS average_salary - Department oda average salary calculate panrom
• MAX(e.salary) AS highest_salary, MIN(e.salary) AS lowest_salary - Maximum and minimum salary find panrom
• LEFT JOIN employees e ON d.department_id = e.department_id - All departments ah include panna LEFT JOIN use panrom
• GROUP BY d.department_id, d.department_name - Department wise group panrom
• Usage: Reporting and analytics ku useful

4. Updatable View with CHECK OPTION - Active employees salary view

CREATE VIEW active_employees_salary AS SELECT employee_id, employee_name, salary, status FROM employees WHERE status = 'ACTIVE' WITH CHECK OPTION;
Line-by-line explanation:
• CREATE VIEW active_employees_salary AS - Updatable view create panrom
• SELECT employee_id, employee_name, salary, status - Update pannavendum columns select panrom
• FROM employees - Base table employees
• WHERE status = 'ACTIVE' - Active employees mattum show panrom
• WITH CHECK OPTION - View condition violate pandra updates ah prevent pannum
• Benefit: INSERT/UPDATE pandrappo automatically status = 'ACTIVE' nu ensure pannum

5. View Management Operations - View modify and drop

-- View structure ah paakalam DESCRIBE employee_basic_info; -- View definition ah paakalam SHOW CREATE VIEW employee_basic_info; -- View ah modify panalam ALTER VIEW employee_basic_info AS SELECT employee_id, employee_name, department_id, hire_date, salary FROM employees WHERE status = 'ACTIVE'; -- View ah delete panalam DROP VIEW IF EXISTS employee_basic_info;
Line-by-line explanation:
• DESCRIBE employee_basic_info; - View oda column structure show pannum
• SHOW CREATE VIEW employee_basic_info; - View create panna query ah show pannum
• ALTER VIEW employee_basic_info AS - Existing view ah modify panrom
• SELECT employee_id, employee_name, department_id, hire_date, salary - New columns add panrom (salary added)
• DROP VIEW IF EXISTS employee_basic_info; - View ah safely delete panrom
• Note: IF EXISTS use pannradhu errors avoid panna help pannum

2. Reporting Dashboard - Executive Summary View

Scenario: Management ku department wise performance summary venum

3. Application Layer Abstraction - API Data Layer

Scenario: Mobile app ku customer order summary data venum, but complex table structure ah hide pananum

CREATE VIEW customer_order_summary AS SELECT c.customer_id, c.customer_name, COUNT(o.order_id) AS total_orders, ROUND(SUM(oi.quantity * oi.unit_price), 2) AS total_spent, MAX(o.order_date) AS last_order_date, CASE WHEN SUM(oi.quantity * oi.unit_price) > 10000 THEN 'Premium' WHEN SUM(oi.quantity * oi.unit_price) > 5000 THEN 'Gold' ELSE 'Regular' END AS customer_tier FROM customers c LEFT JOIN orders o ON c.customer_id = o.customer_id LEFT JOIN order_items oi ON o.order_id = oi.order_id GROUP BY c.customer_id, c.customer_name;

Benefit: Application developers ku simple view kuduthu, complex business logic hide panalam

4. Data Warehouse - Dimension Table Views

Scenario: Analytics team ku clean and formatted dimension data venum

CREATE VIEW dim_employee_clean AS SELECT employee_id, TRIM(UPPER(employee_name)) AS employee_name_clean, department_id, CASE WHEN hire_date < '2020-01-01' THEN 'Experienced' WHEN hire_date < '2023-01-01' THEN 'Mid-level' ELSE 'New' END AS experience_category, CASE WHEN salary < 50000 THEN 'Entry' WHEN salary < 80000 THEN 'Mid' ELSE 'Senior' END AS salary_grade FROM employees WHERE status = 'ACTIVE';

Benefit: ETL processes simplified agi, consistent data format maintain panalam
