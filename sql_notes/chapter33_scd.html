Data Warehouse Basics (Vilakkam)

Dimension Table Yenna?

Dimension Table: Business entities pathi describe panra table. Customer details, product details, employee details, time details pola descriptive information store pannurom. Itha "Who, What, Where, When" questions ku answer panra table nu nenachukalam.

Example: Customer dimension la customer_id, name, address, phone_number, city, state pola columns irukum.
-- Customer Dimension Table CREATE TABLE dim_customer ( customer_id INT PRIMARY KEY, customer_name VARCHAR(100), address VARCHAR(200), city VARCHAR(50), state VARCHAR(50), phone_number VARCHAR(15) );

Fact Table Yenna?

Fact Table: Business transactions and events la numerical measures store panra table. Sales amount, quantity, profit, revenue pola measurable data irukum. Itha "How much, How many" questions ku answer panra table.

Example: Sales fact table la order_id, customer_id, product_id, sales_amount, quantity pola columns irukum.
-- Sales Fact Table CREATE TABLE fact_sales ( sale_id INT PRIMARY KEY, customer_id INT, product_id INT, sale_date DATE, quantity INT, unit_price DECIMAL(10,2), total_amount DECIMAL(10,2), FOREIGN KEY (customer_id) REFERENCES dim_customer(customer_id) );

Dimension vs Fact - Simple ah Purinjukalam

Dimension Table: "Yaaru, Yenna, Enga" pola descriptive data
Fact Table: "Evalavu, Ettanai" pola numerical measurements
Relationship: Fact table dimension tables ah foreign key through connect pannum
Purpose: Analysis and reporting ku use pannurom

SCD Definition (Mukkiya Vilakkam)

Slowly Changing Dimensions (SCD): Data warehousing la dimension table la data slowly change aagumbodhu adha handle panna techniques. Customer address change pannuradhu, employee designation change aagradhu, product category maararadhu pola scenarios la use pannurom.

Yen SCD Mukiyam?
• Historical data ah preserve pannanum
• Current data accurate ah maintain pannanum
• Business analysis ku historical trends venum
• Audit and compliance requirements meet pannanum

SCD Types: Type 0, Type 1, Type 2, Type 3, Type 4, Type 6 nu different strategies irukku. Real projects la mostly Type 1, Type 2, Type 3 ah thaan use pannurom.

Flow Chart (Otta Padal)

SCD IMPLEMENTATION PROCESS:
Data Change Detect → History Required Check → SCD Type Select → Implementation Strategy → Data Validation → Historical Analysis Enable
TYPE 2 DETAILED PROCESS:
New Data Arrive → Current Record Find → Values Compare → Different Ah? → Yes: Current Record Close → New Record Insert → Effective Dates Update
QUERY STRATEGY:
Current Data Query → Active Records Filter → Historical Analysis → Time Range Apply → Business Logic Execute

SCD Types Detailed Explanation

Type 0 - Retain Original (Static Data)

Concept: Data ah kabadiyum change pannakoodathu. Birth date, SSN pola permanent data ku use pannurom.
Implementation: Table la constraints vachtu update block pannurom.

Type 1 - Overwrite (Current State)

Concept: Pudhiya data vandhaale pazhaya data completely replace pannurom.
Pros: Simple, storage less
Cons: History lose aagum

Type 2 - Add New Record (Full History)

Concept: Every change ku pudhiya record create pannurom.
Pros: Complete history maintain aagum
Cons: Storage adhigam, queries complex

Type 3 - Add New Attribute (Limited History)

Concept: Previous value store panna separate column add pannurom.
Pros: Current & previous value rendu theriyum
Cons: Only one previous value maintain aagum

Type 4 - History Table (Separate Archive)

Concept: Current and historical data separate tables la maintain pannurom.
Use Case: Performance important places la use pannurom

Type 6 - Hybrid Approach (Type 1+2+3)

Concept: Multiple SCD techniques combine pannurom.
Use Case: Complex business requirements ku

Example 5: SCD Implementation with Stored Procedures

-- Automated SCD Type 2 Implementation DELIMITER // CREATE PROCEDURE UpdateEmployeeSCD( IN p_employee_id INT, IN p_employee_name VARCHAR(100), IN p_designation VARCHAR(50), IN p_salary DECIMAL(10,2), IN p_department VARCHAR(50) ) BEGIN DECLARE v_current_exists INT DEFAULT 0; DECLARE v_data_changed INT DEFAULT 0; -- Check if current record exists SELECT COUNT(*) INTO v_current_exists FROM dim_employee_type2 WHERE employee_id = p_employee_id AND is_current_record = 'Y'; -- If current record exists, check for changes IF v_current_exists > 0 THEN SELECT COUNT(*) INTO v_data_changed FROM dim_employee_type2 WHERE employee_id = p_employee_id AND is_current_record = 'Y' AND (designation != p_designation OR salary != p_salary OR department != p_department); END IF; -- If data changed, implement SCD Type 2 IF v_data_changed > 0 THEN -- Close current record UPDATE dim_employee_type2 SET expiry_date = CURDATE() - INTERVAL 1 DAY, is_current_record = 'N' WHERE employee_id = p_employee_id AND is_current_record = 'Y'; -- Insert new record INSERT INTO dim_employee_type2 (employee_id, employee_name, designation, department, salary, effective_date, expiry_date) VALUES (p_employee_id, p_employee_name, p_designation, p_department, p_salary, CURDATE(), '9999-12-31'); ELSEIF v_current_exists = 0 THEN -- Insert first record for new employee INSERT INTO dim_employee_type2 (employee_id, employee_name, designation, department, salary, effective_date, expiry_date) VALUES (p_employee_id, p_employee_name, p_designation, p_department, p_salary, CURDATE(), '9999-12-31'); END IF; END // DELIMITER ;
PROCEDURE UpdateEmployeeSCD: Automated ah SCD Type 2 implement panra function
DECLARE v_current_exists: Current record irukka nu check panra variable
DECLARE v_data_changed: Data change aagudha nu check panra variable
IF v_data_changed > 0: Data change aaguna SCD process start aagum
CURDATE() - INTERVAL 1 DAY: Previous record end date yesterday set pannurom
Automation Benefit: Manual errors avoid pannalam, consistent process
-- Using the Stored Procedure CALL UpdateEmployeeSCD(201, 'Anand Kumar', 'Team Lead', 75000.00, 'IT'); -- Verify the update SELECT employee_id, employee_name, designation, salary, effective_date, expiry_date, is_current_record FROM dim_employee_type2 WHERE employee_id = 201 ORDER BY effective_date;
CALL UpdateEmployeeSCD: Procedure ah execute pannurom
Parameters: Employee details pass pannurom
Automatic Process: Procedure automatic ah SCD logic implement pannum
Verify Query: Changes correct ah implement aagudha nu check pannurom

Definition (Vilakkam)

ACID Properties: Database transactions la data integrity maintain panna follow panna veenda 4 fundamental properties. Atomicity, Consistency, Isolation, Durability nu 4 pillars irukku. Banking, financial systems pola critical applications la ACID compliance romba important.

Atomicity Example:

-- Bank Account Transfer Example START TRANSACTION; -- Debit from source account UPDATE bank_accounts SET balance = balance - 10000 WHERE account_number = 'ACC001'; -- Credit to destination account UPDATE bank_accounts SET balance = balance + 10000 WHERE account_number = 'ACC002'; -- If any error occurs anywhere, entire transaction rollback aagum -- Both operations success aaganum illa rendu layum rollback aaganum COMMIT; -- Success case la permanent ah save pannurom -- ROLLBACK; -- Error case la everything undo pannurom
START TRANSACTION: Transaction boundary start pannurom
Atomicity Principle: All or nothing - partial success allow pannaathu
Real Scenario: Money transfer la amount debit aagudhu aana credit aagala na dangerous
COMMIT: Everything successful aana permanent ah save pannurom
ROLLBACK: Any error vandha complete transaction undo pannurom
