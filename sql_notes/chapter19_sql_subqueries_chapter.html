📖 Definition (Sub Queries enna?)

Sub Query na oru main query kulla execute agra another query thaan. Idha nested query or inner query nu kooda solvanga.

Sub queries oda main purpose:

  • Complex data filtering panna
  • Dynamic values ku based ah conditions vekkalam
  • Multiple tables la irundhu related data get panalam
  • Conditional logic implement panalam
  • Data comparison operations perform panalam

🎯 Sub Query Basic Structure:

Outer Query (Main Query) + Inner Query (Sub Query)

SELECT column1 FROM table1 WHERE column2 = (SELECT column3 FROM table2 WHERE condition);

🏛️ Standard (Sub Queries Types & Standards)

MySQL la sub queries ah different categories la classify panalam:

Sub Query Type Description Usage
Single Row Sub Query Oru single value return pannum =, !=, <, > operators oda use panalam
Multiple Row Sub Query Multiple values return pannum IN, NOT IN, ANY, ALL operators use pananum
Correlated Sub Query Outer query oda dependency irukum Row-by-row processing pannum
Non-Correlated Sub Query Independent ah execute agum Once execute aachu, result ah reuse pannum
Scalar Sub Query Single value return pannum SELECT clause la use panalam

📍 Sub Query Positions:

  • WHERE clause: Filtering conditions ku
  • FROM clause: Virtual table ah use panna
  • SELECT clause: Calculated columns ku
  • HAVING clause: Group filtering ku

🎯 Examples with Detailed Explanation

1. Single Row Sub Query - Maximum salary ah earn pandra employee find panna

SELECT employee_name, salary FROM employees WHERE salary = (SELECT MAX(salary) FROM employees);
Line-by-line explanation:
• SELECT employee_name, salary - Employee name and salary columns ah select panrom
• FROM employees - employees table la irundhu data retrieve panrom
• WHERE salary = - Salary column ku condition apply panrom
• (SELECT MAX(salary) FROM employees) - Sub query: employees table la maximum salary ah find pannum
• Process: First sub query execute agi maximum salary value return pannum, aprom main query adha use panni matching employee ah find pannum

2. Multiple Row Sub Query - IT department employees ah find panna

SELECT employee_name, department_id FROM employees WHERE department_id IN (SELECT department_id FROM departments WHERE department_name = 'IT');
Line-by-line explanation:
• SELECT employee_name, department_id - Employee details select panrom
• FROM employees - Main table employees
• WHERE department_id IN - department_id check panna IN operator use panrom
• (SELECT department_id FROM departments WHERE department_name = 'IT') - Sub query: IT department oda ID ah find pannum
• Process: Sub query IT department oda IDs return pannum, main query adha match panni employees ah filter pannum

3. Correlated Sub Query - Each department la average salary vida high earn pandravan find panna

SELECT e1.employee_name, e1.salary, e1.department_id FROM employees e1 WHERE e1.salary > (SELECT AVG(e2.salary) FROM employees e2 WHERE e2.department_id = e1.department_id);
Line-by-line explanation:
• SELECT e1.employee_name, e1.salary, e1.department_id - Outer query employee details select pannum
• FROM employees e1 - Main table ku e1 alias kuduthom
• WHERE e1.salary > - Salary comparison condition
• (SELECT AVG(e2.salary) FROM employees e2 - Sub query: average salary calculate pannum
• WHERE e2.department_id = e1.department_id) - Same department employees ku filter pannum
• Process: Each row ku sub query execute agi, adha department oda average salary calculate panni compare pannum

4. Sub Query in FROM clause - Department wise employee count

SELECT d.department_name, emp_count.total_employees FROM departments d JOIN (SELECT department_id, COUNT(*) AS total_employees FROM employees GROUP BY department_id) emp_count ON d.department_id = emp_count.department_id;
Line-by-line explanation:
• SELECT d.department_name, emp_count.total_employees - Department name and employee count select panrom
• FROM departments d - departments table main table ah use panrom
• JOIN - Sub query result oda join panrom
• (SELECT department_id, COUNT(*) AS total_employees FROM employees GROUP BY department_id) - Sub query: department wise employee count calculate pannum
• emp_count - Sub query result ku alias name
• ON d.department_id = emp_count.department_id - Join condition
• Process: Sub query department wise count return pannum, main query adha department name oda join panni final result kudukum

5. EXISTS Operator with Sub Query - Project assign aana employees ah find panna

SELECT employee_name, employee_id FROM employees e WHERE EXISTS (SELECT 1 FROM project_assignments pa WHERE pa.employee_id = e.employee_id);
Line-by-line explanation:
• SELECT employee_name, employee_id - Employee details select panrom
• FROM employees e - employees table la irundhu data get panrom
• WHERE EXISTS - EXISTS condition check panrom
• (SELECT 1 FROM project_assignments pa - Sub query: project assignments table check pannum
• WHERE pa.employee_id = e.employee_id) - Current employee ku project assignment iruka nu check pannum
• Process: Each employee ku sub query run agi, project assignment irundha TRUE return pannum, illana FALSE

🛠️ Use Cases (Real-world Applications)

1. E-commerce: Best Selling Products Analysis

Scenario: Average sales vida athiga sell aana products ah find pannum

SELECT product_name, total_sales FROM products p WHERE (SELECT SUM(quantity) FROM order_items oi WHERE oi.product_id = p.product_id) > (SELECT AVG(total_quantity) FROM (SELECT SUM(quantity) AS total_quantity FROM order_items GROUP BY product_id) AS avg_sales);

Benefit: High performing products ah identify panni inventory planning panalam

2. HR Management: Department Performance Comparison

Scenario: Company average salary vida high pay pandra departments find pannum

SELECT d.department_name, AVG(e.salary) AS avg_department_salary FROM departments d JOIN employees e ON d.department_id = e.department_id GROUP BY d.department_name HAVING AVG(e.salary) > (SELECT AVG(salary) FROM employees);

Benefit: Budget allocation and salary benchmarking ku use panalam

3. Banking: Loan Approval System

Scenario: Customer oda credit history based ah loan approve pannanuma decide pannum

SELECT customer_id, loan_amount, credit_score FROM loan_applications la WHERE credit_score > (SELECT AVG(credit_score) FROM customers WHERE loan_status = 'APPROVED') AND NOT EXISTS (SELECT 1 FROM defaulted_loans dl WHERE dl.customer_id = la.customer_id);

Benefit: Risk assessment accurate ah panni better loan decisions edukalam

4. Inventory Management: Reorder Point Calculation

Scenario: Average consumption vida kamiya irukra products ah identify pannum

SELECT product_name, current_stock FROM inventory i WHERE current_stock < (SELECT AVG(monthly_consumption) FROM sales_history sh WHERE sh.product_id = i.product_id AND sale_date >= DATE_SUB(CURDATE(), INTERVAL 6 MONTH));

Benefit: Stock-out situations avoid panni customer satisfaction maintain panalam

5. Student Management: Top Performers Identification

Scenario: Each subject la class average vida high marks vaanga students find pannum

SELECT s.student_name, s.student_id, sub.subject_name FROM students s JOIN marks m ON s.student_id = m.student_id JOIN subjects sub ON m.subject_id = sub.subject_id WHERE m.marks > (SELECT AVG(m2.marks) FROM marks m2 WHERE m2.subject_id = m.subject_id);

Benefit: Scholarship allocation and merit recognition ku use panalam
