Chapter 15: Logical Operators (NOT IN, AND, OR, IN, ALIAS)

📖 Definition

Logical Operators: Logical operators use panni multiple conditions combine pannalam, complex filtering pannalam. AND, OR, NOT operators mathematical logic principles follow pannum. IN and NOT IN operators multiple values check panna use panrom. ALIAS column names and table names-ku short names or meaningful names kudukka use panrom.

🎯 Logical Operators Overview

🔗 AND

All Conditions True

All conditions satisfy aana mattum result

condition1 AND condition2

🔀 OR

Any Condition True

Any one condition true-na enough

condition1 OR condition2

📝 IN

Value in List

Value given list-la iruka check pannum

column IN (value1, value2)

🚫 NOT IN

Value Not in List

Value given list-la illa-nu check pannum

column NOT IN (value1, value2)

🔗 AND Operator

-- Basic AND examples - all conditions must be true -- Find IT employees with salary > 50000 SELECT emp_name, department, salary, city FROM employees WHERE department = 'IT' AND salary > 50000; -- Find employees in Chennai with age < 30 SELECT emp_name, age, city, department FROM employees WHERE city = 'Chennai' AND age < 30; -- Multiple AND conditions SELECT emp_name, department, salary, age, city FROM employees WHERE department = 'IT' AND salary > 50000 AND age < 30 AND is_active = TRUE; -- AND with date conditions SELECT emp_name, department, joining_date FROM employees WHERE joining_date >= '2022-01-01' AND joining_date <= '2023-12-31' AND is_active = TRUE;
AND Operator Explanation:
department = 'IT' AND salary > 50000 - IT department-la irukkanum AND salary 50000-ku mela irukkanum
Multiple AND conditions - Ella conditions-um true aana mattum result varum
Date range with AND - Specific period-la join aana employees mattum
Boolean with AND - Active employees mattum filter pannum

🔀 OR Operator

-- Basic OR examples - any condition can be true -- Find employees in IT OR Finance departments SELECT emp_name, department, salary FROM employees WHERE department = 'IT' OR department = 'Finance'; -- Find employees with high salary OR senior age SELECT emp_name, salary, age, department FROM employees WHERE salary > 55000 OR age > 32; -- Find employees in specific cities SELECT emp_name, city, department FROM employees WHERE city = 'Chennai' OR city = 'Mumbai' OR city = 'Bangalore'; -- Complex OR with parentheses SELECT emp_name, department, salary, age FROM employees WHERE (department = 'IT' OR department = 'Finance') AND (salary > 50000 OR age < 30);
OR Operator Explanation:
department = 'IT' OR department = 'Finance' - IT illa Finance-la yaarachu irundhaa enough
salary > 55000 OR age > 32 - High salary illa senior age-la yaaravadhu irundhaa select aagum
Multiple OR conditions - Any one condition true-na result varum
Parentheses with OR - Complex conditions-ku priority set panna use panrom

📝 IN Operator

-- Basic IN examples - check if value exists in list -- Find employees in specific departments SELECT emp_name, department, salary FROM employees WHERE department IN ('IT', 'Finance', 'HR'); -- Find employees with specific ages SELECT emp_name, age, department FROM employees WHERE age IN (26, 28, 30, 32); -- Find employees in metro cities SELECT emp_name, city, department, salary FROM employees WHERE city IN ('Chennai', 'Mumbai', 'Bangalore', 'Delhi'); -- IN with numbers - find specific salary ranges SELECT emp_name, salary, department FROM employees WHERE salary IN (45000.00, 55000.00, 60000.00); -- IN with subquery (advanced example) SELECT emp_name, department, salary FROM employees WHERE department IN ( SELECT DISTINCT department FROM employees WHERE salary > 50000 );
IN Operator Explanation:
department IN ('IT', 'Finance', 'HR') - Department inda 3-la yaadhavadhu irundha select aagum
age IN (26, 28, 30, 32) - Age inda values-la yaadhavadhu match aana select aagum
IN with subquery - Another query result-a IN list-a use pannalam
IN vs OR - IN use panradhu short and clean, multiple OR conditions replace pannum

🚫 NOT IN Operator

-- Basic NOT IN examples - exclude values from list -- Find employees NOT in specific departments SELECT emp_name, department, salary FROM employees WHERE department NOT IN ('Marketing', 'HR'); -- Find employees NOT in specific age range SELECT emp_name, age, department, city FROM employees WHERE age NOT IN (26, 35); -- Find employees NOT in tier-2 cities SELECT emp_name, city, department, salary FROM employees WHERE city NOT IN ('Pune', 'Hyderabad', 'Ahmedabad'); -- NOT IN with NULL handling (important!) SELECT emp_name, department, salary FROM employees WHERE emp_id NOT IN ( SELECT emp_id FROM employees WHERE salary < 50000 AND emp_id IS NOT NULL ); -- Complex NOT IN with multiple conditions SELECT emp_name, department, salary, age FROM employees WHERE department NOT IN ('Marketing') AND age NOT IN (35, 32) AND is_active = TRUE;
NOT IN Operator Explanation:
department NOT IN ('Marketing', 'HR') - Marketing and HR illa-na mathavanga select aagum
age NOT IN (26, 35) - 26 and 35 age illa-na mathavanga
NOT IN with subquery - Subquery result-la illa-na records select pannum
NULL handling important - NOT IN with NULL values unexpected results kudukum

🏷️ ALIAS (Column and Table Aliases)

-- Column aliases - give meaningful names to columns -- Basic column aliases SELECT emp_name AS employee_name, department AS dept, salary AS monthly_salary, age AS employee_age FROM employees WHERE salary > 50000; -- Aliases with calculations SELECT emp_name AS name, salary AS current_salary, salary * 12 AS annual_salary, salary * 1.1 AS salary_after_10_percent_hike, YEAR(CURDATE()) - YEAR(joining_date) AS years_of_experience FROM employees; -- Table aliases for shorter queries SELECT e.emp_name, e.department, e.salary, e.city FROM employees AS e WHERE e.salary > 50000 AND e.is_active = TRUE; -- Multiple table aliases (when using joins) SELECT e.emp_name, e.department, d.department_head, d.budget FROM employees AS e JOIN departments AS d ON e.department = d.dept_name WHERE e.salary > 50000;
ALIAS Explanation:
emp_name AS employee_name - Result-la column name 'employee_name'-a show aagum
salary * 12 AS annual_salary - Calculation result-ku meaningful name kudukurom
employees AS e - Table name-ku short alias kudukkurom
e.emp_name - Table alias use panni column specify pannurom

🔄 Complex Combinations

-- Complex logical combinations with parentheses -- Find IT or Finance employees in specific cities with good salary SELECT emp_name AS name, department AS dept, salary AS pay, city AS location, age FROM employees AS e WHERE (e.department = 'IT' OR e.department = 'Finance') AND (e.city IN ('Chennai', 'Mumbai', 'Bangalore')) AND e.salary > 50000 AND e.is_active = TRUE; -- Find employees with high salary OR (specific department AND age) SELECT emp_name AS employee, department, salary, age, city FROM employees WHERE salary > 60000 OR (department = 'IT' AND age BETWEEN 25 AND 30) OR (city IN ('Chennai', 'Mumbai') AND is_active = TRUE); -- Complex NOT IN with multiple conditions SELECT emp_name AS name, department, salary, city, CASE WHEN salary > 60000 THEN 'High' WHEN salary > 50000 THEN 'Medium' ELSE 'Standard' END AS salary_category FROM employees AS e WHERE e.department NOT IN ('Marketing', 'Admin') AND e.age NOT IN (35, 40, 45) AND (e.city = 'Chennai' OR e.salary > 55000) AND e.is_active = TRUE;

🔧 Use Cases

1. HR Employee Filtering

Scenario: HR-ku specific criteria-oda employees list venum
-- Find active employees in IT/Finance with good salary SELECT emp_name AS employee_name, department, salary AS monthly_pay, city AS work_location FROM employees WHERE department IN ('IT', 'Finance') AND salary > 50000 AND is_active = TRUE AND city NOT IN ('Remote', 'Offshore');

2. Payroll Processing

Scenario: Salary increment eligible employees find pannum
-- Find employees eligible for increment SELECT emp_name AS employee, department AS dept, salary AS current_salary, salary * 1.15 AS new_salary_15_percent_hike, age, YEAR(CURDATE()) - YEAR(joining_date) AS experience_years FROM employees WHERE (salary < 55000 OR age < 30) AND department NOT IN ('Marketing') AND is_active = TRUE AND joining_date <= '2022-12-31';

3. Performance Analysis

Scenario: Department-wise employee analysis
-- Analyze employees by performance criteria SELECT department AS dept, COUNT(*) AS total_employees, AVG(salary) AS avg_salary, COUNT(CASE WHEN salary > 55000 THEN 1 END) AS high_earners, COUNT(CASE WHEN age < 30 THEN 1 END) AS young_employees FROM employees WHERE department IN ('IT', 'Finance', 'HR') AND is_active = TRUE GROUP BY department HAVING AVG(salary) > 50000;

4. Location-based Reporting

Scenario: City-wise employee distribution
-- City-wise active employee report SELECT city AS location, department AS dept, COUNT(*) AS employee_count, ROUND(AVG(salary), 2) AS average_salary, MIN(age) AS youngest_employee_age, MAX(age) AS oldest_employee_age FROM employees WHERE city IN ('Chennai', 'Mumbai', 'Bangalore', 'Delhi') AND is_active = TRUE AND salary NOT IN (0, NULL) GROUP BY city, department ORDER BY location, employee_count DESC;

⚠️ Common Mistakes & Best Practices

Common Mistakes to Avoid:

❌ NULL with NOT IN: NOT IN list-la NULL irundha unexpected results varum
❌ Operator Precedence: AND has higher precedence than OR - parentheses use pannunga
❌ Too Many OR: Multiple OR conditions-ku bajama IN use pannunga
❌ Case Sensitivity: String comparisons case sensitive-a check pannunga
❌ Long Alias Names: Alias names simple and meaningful-a venga

Best Practices:

✅ Use Parentheses: Complex conditions-ku parentheses use panni clarity improve pannunga
✅ Meaningful Aliases: Column aliases descriptive and business-friendly-a venga
✅ IN vs OR: Multiple values check panna IN use pannunga
✅ Handle NULLs: NOT IN with subqueries-la NULL check pannunga
✅ Index Usage: WHERE clause columns-ku index create pannunga performance-ku
✅ Test Queries: Complex conditions small data set-la test pannunga

📊 Performance Tips

Optimization Techniques:

⚡ Index Strategy: Frequently used WHERE columns-ku composite index create pannunga
⚡ Order Conditions: Most selective condition first-a venga
⚡ Use EXISTS: Large subqueries-ku NOT IN bajama NOT EXISTS use pannunga
⚡ LIMIT Results: Large result sets-ku LIMIT use pannunga
⚡ Avoid Functions: WHERE clause-la column functions avoid pannunga

🔄 Alternative Approaches

-- Instead of multiple OR conditions, use IN -- ❌ Avoid this: SELECT emp_name, department FROM employees WHERE department = 'IT' OR department = 'Finance' OR department = 'HR'; -- ✅ Use this instead: SELECT emp_name, department FROM employees WHERE department IN ('IT', 'Finance', 'HR'); -- Instead of NOT IN with NULLs, use NOT EXISTS -- ❌ Problematic with NULLs: SELECT emp_name FROM employees WHERE emp_id NOT IN ( SELECT manager_id FROM departments ); -- ✅ Better approach: SELECT emp_name FROM employees e WHERE NOT EXISTS ( SELECT 1 FROM departments d WHERE d.manager_id = e.emp_id ); -- Use CASE with logical operators for complex conditions SELECT emp_name, department, salary, CASE WHEN department = 'IT' AND salary > 55000 THEN 'IT Senior' WHEN department = 'Finance' AND salary > 60000 THEN 'Finance Senior' WHEN department IN ('HR', 'Marketing') AND age > 30 THEN 'Experienced' ELSE 'Standard' END AS employee_category FROM employees WHERE is_active = TRUE;

📈 Advanced Examples

-- Complex business logic with multiple operators SELECT e.emp_name AS employee_name, e.department AS dept, e.salary AS current_salary, e.city AS location, e.age, CASE WHEN e.salary > 60000 AND e.age < 35 THEN 'High Potential' WHEN e.department IN ('IT', 'Finance') AND e.salary > 50000 THEN 'Core Contributor' WHEN e.age > 32 AND e.salary > 45000 THEN 'Experienced Professional' ELSE 'Standard Employee' END AS employee_tier, -- Calculate bonus eligibility CASE WHEN (e.department = 'IT' AND e.salary > 50000) OR (e.department = 'Finance' AND e.salary > 55000) OR (e.age < 30 AND e.salary > 45000) THEN 'Bonus Eligible' ELSE 'Not Eligible' END AS bonus_status FROM employees AS e WHERE e.is_active = TRUE AND e.city NOT IN ('Remote', 'Contractor') AND ( (e.department IN ('IT', 'Finance') AND e.salary > 45000) OR (e.department = 'HR' AND e.age BETWEEN 25 AND 40) OR (e.department NOT IN ('Marketing', 'Admin') AND e.salary > 55000) ) ORDER BY CASE e.department WHEN 'IT' THEN 1 WHEN 'Finance' THEN 2 WHEN 'HR' THEN 3 ELSE 4 END, e.salary DESC; -- Dynamic filtering with multiple logical conditions SELECT dept_summary.department, dept_summary.total_employees, dept_summary.avg_salary, dept_summary.salary_range, CASE WHEN dept_summary.avg_salary > 55000 THEN 'High Paying' WHEN dept_summary.avg_salary > 45000 THEN 'Competitive' ELSE 'Standard' END AS department_category FROM ( SELECT department, COUNT(*) AS total_employees, ROUND(AVG(salary), 2) AS avg_salary, CONCAT('₹', FORMAT(MIN(salary), 2), ' - ₹', FORMAT(MAX(salary), 2)) AS salary_range FROM employees WHERE is_active = TRUE AND department NOT IN ('Admin', 'Intern') AND (salary > 40000 OR age < 35) GROUP BY department HAVING COUNT(*) > 1 AND AVG(salary) > 40000 ) AS dept_summary WHERE dept_summary.total_employees > 1 ORDER BY dept_summary.avg_salary DESC;

📚 Quick Reference

  • AND: All conditions must be true
  • OR: Any condition can be true
  • IN (list): Value exists in given list
  • NOT IN (list): Value does not exist in given list
  • column AS alias: Give column a different name in result
  • table AS alias: Give table a short name for easier reference
  • Parentheses (): Control operator precedence
  • NULL handling: Be careful with NOT IN and NULL values
