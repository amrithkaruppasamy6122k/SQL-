Vilakkam (Definition)

Database Normalization: Database design la irukka duplicate data (punar takkaal) ah reduce panni, data integrity (takkaal nilai thanmai) ah maintain panna use panra technique. Itha pala normal forms la organize pannurom.

Normalization Target: Data redundancy illa pannu, storage space save pannu, data inconsistency problems avoid pannu, update/insert/delete operations ah easy ah pannu.

Normal Forms: 1NF, 2NF, 3NF, BCNF, 4NF, 5NF nu different levels irukku. Adhulayum mostly 1NF to 3NF varaikum use pannurom.

Otta Padal (Flow Chart)

NORMALIZATION PROCESS:
Unnormalized Table → 1NF (Atomic Values) → 2NF (Partial Dependency Remove) → 3NF (Transitive Dependency Remove) → BCNF (Advanced Normal Form)
DENORMALIZATION PROCESS:
Normalized Tables → Performance Requirements → Join Tables → Add Redundancy → Query Optimization
NORMALIZATION BENEFITS:
Less Storage → No Data Duplication → Easy Maintenance → Better Data Integrity → Reduced Update Anomalies

Normal Forms Vakaigal

1. First Normal Form (1NF) - Muthal Nilai Uruvaakam

Ellaa columns layum atomic values mattum irukanum. Oru cell la multiple values irukka koodaathu.

2. Second Normal Form (2NF) - Rendaam Nilai Uruvaakam

1NF requirements meet pannanum + Partial dependency irukka koodaathu.

3. Third Normal Form (3NF) - Moondraam Nilai Uruvaakam

2NF requirements meet pannanum + Transitive dependency irukka koodaathu.

4. Boyce-Codd Normal Form (BCNF)

3NF ah vida advanced form. Ellaa functional dependencies layum left side super key ah irukanum.

Udaharanangal ooda Vilakkam

Udaharanam 1: First Normal Form (1NF) - Muthal Nilai Uruvaakam

Problem - Prachanaigal:

Oru cell la multiple values irukku. Itha atomic ah illa.

-- Thavaraana Vagai (Before 1NF) CREATE TABLE vidyarthigal_thavaraana ( id INT, peyar VARCHAR(100), vishayangal VARCHAR(200) -- "Kanakkam, Ariviyal, Thamizh" ); INSERT INTO vidyarthigal_thavaraana VALUES (1, 'Ravi Kumar', 'Kanakkam, Ariviyal, Thamizh'), (2, 'Priya Devi', 'Varalaru, Puthagam Nilai, Kalai');
Thavaraana Vagai: vishayangal column la multiple subjects uh comma separate panni store pannurom
Problem: Individual subject ah query panna mudiyaathu
Search Issue: Specific subject irukkanu check panna complex ah irukum
Update Problem: Oru subject ah mattum change panna mudiyaathu

Solution - Teervu:

Ellaa values ayum atomic ah separate pannurom.

-- Sariyaana Vagai (After 1NF) CREATE TABLE vidyarthigal_sariyaana ( id INT, peyar VARCHAR(100), vishayam VARCHAR(50) ); INSERT INTO vidyarthigal_sariyaana VALUES (1, 'Ravi Kumar', 'Kanakkam'), (1, 'Ravi Kumar', 'Ariviyal'), (1, 'Ravi Kumar', 'Thamizh'), (2, 'Priya Devi', 'Varalaru'), (2, 'Priya Devi', 'Puthagam Nilai'), (2, 'Priya Devi', 'Kalai');
Sariyaana Vagai: Oru row la oru subject mattum store pannurom
Atomic Values: Ellaa column layum single value mattum irukku
Query Easy: Individual subject ah easily search pannalam
Maintenance: Update/delete operations easy ah pannalam

Udaharanam 2: Second Normal Form (2NF) - Rendaam Nilai Uruvaakam

Partial Dependency Problem:

Non-key attribute uh, composite key oda part ah mattum depend pannuthu.

-- 2NF illama irukka table CREATE TABLE vidyarthi_vishayam_thavaraana ( vidyarthi_id INT, vishayam_id INT, vishayam_peyar VARCHAR(100), -- Partial dependency adhyaapagar_peyar VARCHAR(100), -- Partial dependency markku INT, PRIMARY KEY (vidyarthi_id, vishayam_id) );
Partial Dependency: vishayam_peyar uh vishayam_id ah mattum depend pannuthu
Problem: Same vishayam_peyar ellaa rows layum repeat aagum
Redundancy: Storage space waste aagum
Update Anomaly: Vishayam peyar change pannana ellaa places layum change pannanum

2NF Solution:

Separate tables create panni partial dependency ah remove pannurom.

-- 2NF Form - Separate tables CREATE TABLE vidyarthigal ( vidyarthi_id INT PRIMARY KEY, vidyarthi_peyar VARCHAR(100) ); CREATE TABLE vishayangal ( vishayam_id INT PRIMARY KEY, vishayam_peyar VARCHAR(100), adhyaapagar_peyar VARCHAR(100) ); CREATE TABLE markku_taalikka ( vidyarthi_id INT, vishayam_id INT, markku INT, PRIMARY KEY (vidyarthi_id, vishayam_id), FOREIGN KEY (vidyarthi_id) REFERENCES vidyarthigal(vidyarthi_id), FOREIGN KEY (vishayam_id) REFERENCES vishayangal(vishayam_id) );
vidyarthigal table: Vidyarthi details mattum store pannurom
vishayangal table: Subject details mattum separate ah store pannurom
markku_taalikka: Marks mattum store panra junction table
FOREIGN KEY: Tables ku naduvula relationship establish pannurom
No Redundancy: Subject name ellaa places layum repeat aagaathu

Udaharanam 3: Third Normal Form (3NF) - Moondraam Nilai Uruvaakam

Transitive Dependency Problem:

Non-key attribute uh, vera oru non-key attribute ah depend pannuthu.

-- 3NF illama irukka table CREATE TABLE alkalargal_thavaraana ( alkalkar_id INT PRIMARY KEY, peyar VARCHAR(100), vibhaagam VARCHAR(50), vibhaaga_thalaivar VARCHAR(100) -- Transitive dependency ); INSERT INTO alkalargal_thavaraana VALUES (1, 'Ravi', 'IT', 'Senthil Kumar'), (2, 'Priya', 'IT', 'Senthil Kumar'), (3, 'Arun', 'Accounts', 'Meena Devi');
Transitive Dependency: vibhaaga_thalaivar uh vibhaagam ah depend pannuthu
Problem: Same department la irukka ellaarukkum same head repeat aagum
Update Anomaly: Department head change aana ellaa rows layum change pannanum
Storage Waste: Same data multiple times store aagum

3NF Solution:

Department details ah separate table la move pannurom.

-- 3NF Form - Separate department table CREATE TABLE vibhaagangal ( vibhaaga_id INT PRIMARY KEY, vibhaaga_peyar VARCHAR(50), vibhaaga_thalaivar VARCHAR(100) ); CREATE TABLE alkalargal_sariyaana ( alkalkar_id INT PRIMARY KEY, peyar VARCHAR(100), vibhaaga_id INT, FOREIGN KEY (vibhaaga_id) REFERENCES vibhaagangal(vibhaaga_id) ); INSERT INTO vibhaagangal VALUES (1, 'IT', 'Senthil Kumar'), (2, 'Accounts', 'Meena Devi'); INSERT INTO alkalargal_sariyaana VALUES (1, 'Ravi', 1), (2, 'Priya', 1), (3, 'Arun', 2);
vibhaagangal table: Department details ah separate ah store pannurom
alkalargal_sariyaana: Employee details layum department reference mattum
vibhaaga_id: Foreign key use panni relationship maintain pannurom
No Transitive Dependency: Department head direct ah depend aagaathu
Easy Maintenance: Department head change aana oru place la mattum change pannaal podhum

Udaharanam 4: Denormalization - Punar Nilai Uruvaakkam

Denormalization: Normalized tables ah purposely join panni performance increase pannuradhu. Read operations frequent ah irundha redundancy add panni query speed increase pannurom.
-- Normalized tables (Multiple joins required) SELECT a.peyar, v.vibhaaga_peyar, v.vibhaaga_thalaivar FROM alkalargal_sariyaana a JOIN vibhaagangal v ON a.vibhaaga_id = v.vibhaaga_id; -- Denormalized table (Single table query) CREATE TABLE alkalargal_denormalized ( alkalkar_id INT PRIMARY KEY, peyar VARCHAR(100), vibhaaga_peyar VARCHAR(50), vibhaaga_thalaivar VARCHAR(100) );
Normalized Query: Rendu tables ah join panni data vaanganum
Performance Issue: Join operations time consuming aagum
Denormalized Table: Ellaam oru table layae store pannurom
Performance Gain: Join venaam, single query podhum
Trade-off: Storage increase aagum aana speed increase aagum

Normalization Steps - Padal Muaigal

Padal 1: 1NF ku Convert pannu

• Ellaa columns layum atomic values mattum vaikka venumu
• Multi-valued attributes ah separate rows ah convert pannu
• Repeated groups ah eliminate pannu

Padal 2: 2NF ku Convert pannu

• 1NF requirements meet pannanum
• Partial functional dependencies ah identify pannu
• Separate tables create panni partial dependencies ah remove pannu

Padal 3: 3NF ku Convert pannu

• 2NF requirements meet pannanum
• Transitive dependencies ah identify pannu
• Non-key attributes ah separate tables la move pannu

Padal 4: BCNF ku Convert pannu (Optional)

• 3NF requirements meet pannanum
• Ellaa functional dependencies layum left side super key ah irukanum
• Advanced normalization technique

Payan Paadu Nilai (Use Cases)

1. Kalvi Nuvana Muramai (Educational Management)

Vidyarthi details, vishaya details, adhyaapagar details ellaam separate tables la normalize panni storage space save pannalam, data consistency maintain pannalam.

2. Velai Paari Muramai (Employee Management)

Alkalkar details, vibhaaga details, payir details ellaam normalize panni redundant data avoid pannalam, update operations easy ah pannalam.

3. Kadai Nilai Muramai (E-commerce System)

Customer details, product details, order details ellaam proper ah normalize panni data integrity maintain pannalam, complex queries easy ah write pannalam.

4. Vaidya Muramai (Healthcare System)

Patient details, doctor details, treatment details ellaam normalize panni duplicate data avoid pannalam, privacy and security maintain pannalam.

Adutta Adhyayam Sample: SCD (Slowly Changing Dimensions)

Vilakkam

SCD (Slowly Changing Dimensions): Data warehousing la dimension table la irukka data ah slowly change aagumbodhu adha handle panna use panra techniques. Customer address change aagradhu, employee designation change aagradhu pola historical data ah track pannurom.

SCD Type 1 Udaharanam:

-- SCD Type 1 - Overwrite method -- Pudhiya data vanthaale pazhaya data ah replace pannidurom UPDATE customers SET address = 'Chennai New Area', updated_date = NOW() WHERE customer_id = 101;
Type 1 Method: Pazhaya data ah completely overwrite pannurom
UPDATE customers: Customer table la address ah update pannurom
No History: Previous address history maintain pannurom illa
Simple Method: Easy ah implement pannalam aana history illa
