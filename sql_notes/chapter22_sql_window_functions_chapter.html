📖 Definition (Window Functions Enna Da?)

Window Functions na oru row ku related ah mathra rows oda comparison panni calculation panra special functions thaan. Idhu normal aggregate functions maari illa - oru single value return panradhu illa, each row ku separate value return pannum.

Window Functions oda mukkiya features:

  • Row-by-row calculation: Oru row ku mathra rows compare panni value return pannum
  • Partitioning: Data ah groups la divide panni each group kulla calculation pannum
  • Ordering: Rows ah specific order la arrange panni calculation pannum
  • Frame specification: Calculation ku enga rows use pananum nu define panalam
  • Ranking functions: Data ah rank panna, dense rank panna use aagum

🎯 Window Function Basic Syntax:

function_name() OVER (PARTITION BY column ORDER BY column ROWS/RANGE frame)

OVER clause thaan window function ah identify panra main component!

⚠️ Mukkiyamana Vishayangal:

  • Window functions SELECT clause la mattum use panna mudiyum
  • WHERE clause la direct ah use panna mudiyathu, HAVING la use panalam
  • Performance ku proper indexing venum PARTITION BY aur ORDER BY columns la
  • Large datasets la use pannum bodhu memory usage jaasthi aagum

🏛️ Standard (Window Functions Types aur Avanga Velai)

MySQL la namma different types oda window functions use panna mudiyum:

Function Type Tamil la Explanation Common Functions
Ranking Functions Data ah rank order la arrange panna use aagum ROW_NUMBER(), RANK(), DENSE_RANK()
Aggregate Functions Window frame kulla calculation panna SUM(), AVG(), COUNT(), MIN(), MAX()
Value Functions Specific position la irukra value ah get panna LAG(), LEAD(), FIRST_VALUE(), LAST_VALUE()
Distribution Functions Data distribution aur percentile calculate panna PERCENT_RANK(), CUME_DIST(), NTILE()

📍 Window Function Components:

  • PARTITION BY: Data ah groups la divide pannum (like GROUP BY but rows preserve aagum)
  • ORDER BY: Window kulla rows ah sort pannum
  • ROWS/RANGE: Window frame size define pannum (current row around enga vara rows use pananum)
  • Frame boundaries: UNBOUNDED PRECEDING, CURRENT ROW, UNBOUNDED FOLLOWING

🎯 Examples with Full Tamil Explanation

1. ROW_NUMBER() - Each row ku unique number assign panradhu

SELECT employee_name, department_id, salary, ROW_NUMBER() OVER ( PARTITION BY department_id ORDER BY salary DESC ) AS salary_rank FROM employees WHERE status = 'ACTIVE' ORDER BY department_id, salary_rank;
Line-by-line Tamil Explanation:
• SELECT employee_name, department_id, salary - Employee details select panrom
• ROW_NUMBER() OVER - Row number assign panna window function start panrom
• PARTITION BY department_id - Department wise groups create panrom
• ORDER BY salary DESC - Each department kulla salary high to low order panrom
• AS salary_rank - Result column ku alias name kudukrom
• FROM employees - employees table la irundhu data edukrom
• WHERE status = 'ACTIVE' - Active employees mattum filter panrom
• ORDER BY department_id, salary_rank - Final result ah department aur rank wise sort panrom
• Result: Each dept la highest salary 1, second highest 2 nu rank assign aagum

2. RANK() aur DENSE_RANK() - Duplicate values handle panra ranking

SELECT student_name, class_id, total_marks, RANK() OVER ( PARTITION BY class_id ORDER BY total_marks DESC ) AS normal_rank, DENSE_RANK() OVER ( PARTITION BY class_id ORDER BY total_marks DESC ) AS dense_rank FROM students WHERE academic_year = '2024-25' ORDER BY class_id, total_marks DESC;
Line-by-line Tamil Explanation:
• SELECT student_name, class_id, total_marks - Student basic details select panrom
• RANK() OVER (PARTITION BY class_id ORDER BY total_marks DESC) - Class wise normal rank assign panrom
• AS normal_rank - Normal rank column alias
• DENSE_RANK() OVER (PARTITION BY class_id ORDER BY total_marks DESC) - Class wise dense rank assign panrom
• AS dense_rank - Dense rank column alias
• FROM students - students table data
• WHERE academic_year = '2024-25' - Current academic year filter
• ORDER BY class_id, total_marks DESC - Class aur marks wise sort
• Difference: RANK() la gaps irukum (1,2,2,4), DENSE_RANK() la gaps illa (1,2,2,3)

3. LAG() aur LEAD() - Previous/Next row data compare panradhu

SELECT sales_date, daily_revenue, LAG(daily_revenue, 1) OVER ( ORDER BY sales_date ) AS previous_day_revenue, LEAD(daily_revenue, 1) OVER ( ORDER BY sales_date ) AS next_day_revenue, daily_revenue - LAG(daily_revenue, 1) OVER ( ORDER BY sales_date ) AS revenue_difference FROM daily_sales WHERE sales_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) ORDER BY sales_date;
Line-by-line Tamil Explanation:
• SELECT sales_date, daily_revenue - Date aur revenue select panrom
• LAG(daily_revenue, 1) OVER (ORDER BY sales_date) - Previous day oda revenue get panrom
• AS previous_day_revenue - Previous day revenue alias
• LEAD(daily_revenue, 1) OVER (ORDER BY sales_date) - Next day oda revenue get panrom
• AS next_day_revenue - Next day revenue alias
• daily_revenue - LAG(daily_revenue, 1) - Current day minus previous day difference calculate panrom
• AS revenue_difference - Difference alias
• FROM daily_sales - daily_sales table data
• WHERE sales_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) - Last 30 days data mattum
• Usage: Daily revenue trend analysis panradhu ku perfect

4. SUM() OVER - Running total calculate panradhu

SELECT transaction_date, transaction_amount, transaction_type, SUM( CASE WHEN transaction_type = 'CREDIT' THEN transaction_amount ELSE -transaction_amount END ) OVER ( ORDER BY transaction_date ROWS UNBOUNDED PRECEDING ) AS running_balance FROM account_transactions WHERE account_id = 1001 AND transaction_date >= DATE_SUB(CURDATE(), INTERVAL 90 DAY) ORDER BY transaction_date;
Line-by-line Tamil Explanation:
• SELECT transaction_date, transaction_amount, transaction_type - Transaction details select panrom
• SUM(CASE WHEN transaction_type = 'CREDIT' THEN transaction_amount - Credit aana amount ah positive ah edukrom
• ELSE -transaction_amount END) - Debit aana amount ah negative ah edukrom
• OVER (ORDER BY transaction_date - Date wise order panni window create panrom
• ROWS UNBOUNDED PRECEDING) - First row la irundhu current row varaikum sum panrom
• AS running_balance - Running balance alias
• FROM account_transactions - account_transactions table data
• WHERE account_id = 1001 - Specific account filter
• AND transaction_date >= DATE_SUB(CURDATE(), INTERVAL 90 DAY) - Last 90 days data
• Result: Each row la account balance show aagum cumulative ah

5. NTILE() - Data ah equal buckets la divide panradhu

SELECT product_name, total_sales_amount, NTILE(4) OVER ( ORDER BY total_sales_amount DESC ) AS sales_quartile, CASE WHEN NTILE(4) OVER (ORDER BY total_sales_amount DESC) = 1 THEN 'Top Performers' WHEN NTILE(4) OVER (ORDER BY total_sales_amount DESC) = 2 THEN 'Good Performers' WHEN NTILE(4) OVER (ORDER BY total_sales_amount DESC) = 3 THEN 'Average Performers' ELSE 'Low Performers' END AS performance_category FROM product_sales_summary WHERE sales_year = 2024 ORDER BY total_sales_amount DESC;
Line-by-line Tamil Explanation:
• SELECT product_name, total_sales_amount - Product name aur sales amount select panrom
• NTILE(4) OVER (ORDER BY total_sales_amount DESC) - Data ah 4 equal parts la divide panrom
• AS sales_quartile - Quartile number alias
• CASE WHEN NTILE(4) OVER (...) = 1 THEN 'Top Performers' - First quartile ah top performers nu mark panrom
• WHEN NTILE(4) OVER (...) = 2 THEN 'Good Performers' - Second quartile good performers
• WHEN NTILE(4) OVER (...) = 3 THEN 'Average Performers' - Third quartile average
• ELSE 'Low Performers' END AS performance_category - Fourth quartile low performers
• FROM product_sales_summary - Sales summary table data
• WHERE sales_year = 2024 - 2024 year data mattum
• Usage: Product performance analysis ku perfect, equal distribution guarantee

🛠️ Use Cases (Real-world la Epidi Use Panradhu)

1. Sales Analytics - Monthly Revenue Trend Analysis

Situation: Each month oda revenue aur previous months oda comparison venum

SELECT sales_month, monthly_revenue, LAG(monthly_revenue, 1) OVER ( ORDER BY sales_month ) AS previous_month_revenue, ROUND( (monthly_revenue - LAG(monthly_revenue, 1) OVER (ORDER BY sales_month)) / LAG(monthly_revenue, 1) OVER (ORDER BY sales_month) * 100, 2 ) AS revenue_growth_percentage, SUM(monthly_revenue) OVER ( ORDER BY sales_month ROWS UNBOUNDED PRECEDING ) AS cumulative_revenue FROM monthly_sales_summary WHERE sales_year = 2024 ORDER BY sales_month;

Faayda: Management ku month-to-month growth trend clear ah theriyum, business planning panradhu ku useful

2. HR Analytics - Employee Performance Ranking

Situation: Department wise employee performance rank pannum, salary increment ku use panalam

SELECT employee_name, department_name, performance_score, salary, RANK() OVER ( PARTITION BY department_name ORDER BY performance_score DESC ) AS dept_performance_rank, PERCENT_RANK() OVER ( PARTITION BY department_name ORDER BY performance_score DESC ) AS performance_percentile, CASE WHEN PERCENT_RANK() OVER (PARTITION BY department_name ORDER BY performance_score DESC) <= 0.1 THEN 'Top 10%' WHEN PERCENT_RANK() OVER (PARTITION BY department_name ORDER BY performance_score DESC) <= 0.25 THEN 'Top 25%' ELSE 'Others' END AS performance_tier FROM employee_performance_review WHERE review_year = 2024 ORDER BY department_name, performance_score DESC;

Faayda: HR team ku fair ah performance based increments aur promotions decide panna mudiyum

3. Finance - Account Balance Monitoring

Situation: Customer account la daily balance track pannum, overdraft situations identify pannum

SELECT transaction_date, transaction_description, transaction_amount, transaction_type, SUM( CASE WHEN transaction_type = 'CREDIT' THEN transaction_amount ELSE -transaction_amount END ) OVER ( ORDER BY transaction_date, transaction_id ROWS UNBOUNDED PRECEDING ) AS daily_balance, MIN( SUM( CASE WHEN transaction_type = 'CREDIT' THEN transaction_amount ELSE -transaction_amount END ) OVER ( ORDER BY transaction_date, transaction_id ROWS UNBOUNDED PRECEDING ) ) OVER ( ORDER BY transaction_date ROWS BETWEEN CURRENT ROW AND UNBOUNDED FOLLOWING ) AS minimum_future_balance FROM account_transactions WHERE account_number = 'ACC123456' AND transaction_date >= DATE_SUB(CURDATE(), INTERVAL 3 MONTH) ORDER BY transaction_date, transaction_id;

Faayda: Bank ku customer oda cash flow pattern theriyum, overdraft risk predict panna mudiyum

4. Inventory Management - Stock Movement Analysis

Situation: Product wise stock in/out movement track pannum, reorder point calculate pannum

SELECT movement_date, product_name, movement_type, quantity, SUM( CASE WHEN movement_type = 'IN' THEN quantity ELSE -quantity END ) OVER ( PARTITION BY product_name ORDER BY movement_date ROWS UNBOUNDED PRECEDING ) AS current_stock_level, AVG( CASE WHEN movement_type = 'OUT' THEN quantity ELSE 0 END ) OVER ( PARTITION BY product_name ORDER BY movement_date ROWS BETWEEN 6 PRECEDING AND CURRENT ROW ) AS avg_weekly_consumption, FIRST_VALUE(movement_date) OVER ( PARTITION BY product_name ORDER BY movement_date ROWS UNBOUNDED PRECEDING ) AS first_movement_date FROM stock_movements WHERE movement_date >= DATE_SUB(CURDATE(), INTERVAL 6 MONTH) ORDER BY product_name, movement_date;

Faayda: Inventory manager ku stock trends theriyum, automatic reorder alerts setup panna mudiyum

5. Website Analytics - User Session Analysis

Situation: User behavior track pannum, session duration aur page views calculate pannum

SELECT user_id, session_start_time, page_url, page_view_time, LEAD(page_view_time, 1) OVER ( PARTITION BY user_id, session_id ORDER BY page_view_time ) AS next_page_time, COALESCE( LEAD(page_view_time, 1) OVER ( PARTITION BY user_id, session_id ORDER BY page_view_time ) - page_view_time, 0 ) AS time_spent_seconds, ROW_NUMBER() OVER ( PARTITION BY user_id, session_id ORDER BY page_view_time ) AS page_sequence, COUNT(*) OVER ( PARTITION BY user_id, session_id ) AS total_pages_in_session FROM user_page_views WHERE session_date >= DATE_SUB(CURDATE(), INTERVAL 7 DAY) ORDER BY user_id, session_id, page_view_time;

Faayda: Marketing team ku user engagement patterns theriyum, website optimization panna mudiyum
