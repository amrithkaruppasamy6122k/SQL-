📖 Definition (Regular Expressions Enna Thalaiva?)

Regular Expressions (Regex) na text data la specific patterns ah search panradhu, match panradhu, aur replace panradhu ku use agura powerful technique thaan. Idhu programming world oda Swiss Army Knife maari - text processing ku ellam solution irukum!

MySQL la Regex oda super powers:

  • Pattern Matching: Complex text patterns ah precisely identify panna mudiyum
  • Data Validation: Email, phone, postal codes validation super easy
  • Text Extraction: String la specific portions ah extract panna mudiyum
  • Data Cleaning: Unwanted characters, formats ah clean panna mudiyum
  • Advanced Search: Simple LIKE operator vida powerful search operations
  • Format Standardization: Different formats la irukra data ah uniform ah convert panalam

🎯 MySQL Regex Functions:

  • REGEXP / RLIKE: Pattern match checking (TRUE/FALSE return pannum)
  • REGEXP_LIKE(): Pattern match with additional options
  • REGEXP_SUBSTR(): First matching substring extract pannum
  • REGEXP_REPLACE(): Pattern-based text replacement
  • REGEXP_INSTR(): Pattern match position find pannum

🔍 Common Regex Patterns:

  • ^: String start (line beginning)
  • $: String end (line ending)
  • . Any single character
  • *: Zero or more occurrences
  • +: One or more occurrences
  • ?: Zero or one occurrence
  • [abc]: Any one of a, b, or c
  • [0-9]: Any digit from 0 to 9
  • \d: Any digit (equivalent to [0-9])
  • \w: Any word character (alphanumeric + underscore)

⚠️ Regex la Careful Ah Irukanume:

  • Performance Impact: Complex regex patterns query speed slow pannum
  • Case Sensitivity: Default ah case-sensitive matching aagum
  • Special Characters: Meta characters ah escape pananum
  • Pattern Complexity: Over-complex patterns maintain panna kashtam
  • Index Usage: Regex conditions la index utilization limited

🎯 Examples with Full Tamil Explanation

1. Basic Pattern Matching - Simple regex operations

-- Email validation using regex SELECT customer_id, customer_name, email_address, CASE WHEN email_address REGEXP '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$' THEN 'Valid Email' ELSE 'Invalid Email' END AS email_status FROM customers WHERE email_address IS NOT NULL ORDER BY email_status, customer_name; -- Phone number validation - Indian mobile numbers SELECT customer_id, customer_name, phone_number, CASE WHEN phone_number REGEXP '^[6-9][0-9]{9}$' THEN 'Valid Mobile' WHEN phone_number REGEXP '^(\+91)?[6-9][0-9]{9}$' THEN 'Valid with Country Code' ELSE 'Invalid Number' END AS phone_status FROM customers WHERE phone_number IS NOT NULL; -- PIN code validation SELECT address_id, customer_id, postal_code, CASE WHEN postal_code REGEXP '^[1-9][0-9]{5}$' THEN 'Valid PIN Code' ELSE 'Invalid PIN Code' END AS pin_status FROM customer_addresses WHERE postal_code IS NOT NULL;
Line-by-line Tamil Explanation:
• email_address REGEXP '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$' - Email format validation pattern
• ^[A-Za-z0-9._%+-]+ - Email oda first part (username) - letters, numbers, special chars allowed
• @[A-Za-z0-9.-]+ - @ symbol apram domain name part
• \.[A-Za-z]{2,}$ - Dot apram minimum 2 letters domain extension (.com, .org, etc.)
• phone_number REGEXP '^[6-9][0-9]{9}$' - Indian mobile number pattern (10 digits, 6-9 la start aaganum)
• '^(\+91)?[6-9][0-9]{9}$' - Optional country code (+91) oda mobile number
• postal_code REGEXP '^[1-9][0-9]{5}$' - Indian PIN code (6 digits, 1-9 la start aaganum, 0 la start aagakoodadhu)
• Business Value: Data quality ensure pannum, invalid contacts identify panalam
• Validation Power: Real-time data validation, user registration form validation

2. Text Extraction - Pattern based data extraction

-- Extract domain name from email addresses SELECT customer_id, email_address, REGEXP_SUBSTR(email_address, '@(.+)', 1, 1, '', 1) AS domain_name, CASE WHEN REGEXP_SUBSTR(email_address, '@(.+)', 1, 1, '', 1) IN ('gmail.com', 'yahoo.com', 'hotmail.com') THEN 'Personal Email' ELSE 'Business Email' END AS email_type FROM customers WHERE email_address REGEXP '^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$' ORDER BY domain_name; -- Extract area code from phone numbers SELECT customer_id, phone_number, CASE WHEN phone_number REGEXP '^\+91[6-9][0-9]{9}$' THEN REGEXP_SUBSTR(phone_number, '\+91([6-9][0-9]{2})', 1, 1, '', 1) WHEN phone_number REGEXP '^[6-9][0-9]{9}$' THEN REGEXP_SUBSTR(phone_number, '^([6-9][0-9]{2})', 1, 1, '', 1) ELSE NULL END AS area_code, LENGTH(phone_number) AS phone_length FROM customers WHERE phone_number IS NOT NULL AND phone_number REGEXP '(^\+91[6-9][0-9]{9}$|^[6-9][0-9]{9}$)'; -- Extract numbers from mixed text SELECT product_code, product_name, REGEXP_SUBSTR(product_name, '[0-9]+', 1, 1) AS first_number, REGEXP_SUBSTR(product_name, '[0-9]+', 1, 2) AS second_number, REGEXP_SUBSTR(product_name, '[A-Za-z]+', 1, 1) AS first_text_part FROM products WHERE product_name REGEXP '[0-9]+' ORDER BY product_code;
Line-by-line Tamil Explanation:
• REGEXP_SUBSTR(email_address, '@(.+)', 1, 1, '', 1) AS domain_name - Email address la irundhu domain name extract panrom
• '@(.+)' - @ symbol apram vara ellam characters ah capture panrom
• 1, 1, '', 1 - Position 1 la irundhu start, first occurrence, no flags, capture group 1
• WHEN REGEXP_SUBSTR(...) IN ('gmail.com', 'yahoo.com', 'hotmail.com') - Popular personal email domains check panrom
• REGEXP_SUBSTR(phone_number, '\+91([6-9][0-9]{2})', 1, 1, '', 1) - Country code oda phone number la irundhu area code extract panrom
• '^([6-9][0-9]{2})' - Phone number start la irundhu first 3 digits (area code) capture panrom
• REGEXP_SUBSTR(product_name, '[0-9]+', 1, 1) - Product name la first number extract panrom
• REGEXP_SUBSTR(product_name, '[0-9]+', 1, 2) - Product name la second number extract panrom
• Data Mining: Structured data unstructured text la irundhu extract panalam
• Analytics: Email domains, area codes, product codes analyze panalam

3. Data Cleaning and Standardization - Pattern-based replacement

-- Clean and standardize phone numbers SELECT customer_id, phone_number AS original_phone, REGEXP_REPLACE(phone_number, '[^0-9+]', '') AS digits_only, CASE WHEN phone_number REGEXP '^\+91' THEN REGEXP_REPLACE(phone_number, '[^0-9]', '') WHEN phone_number REGEXP '^91[6-9][0-9]{9}$' THEN CONCAT('+', REGEXP_REPLACE(phone_number, '[^0-9]', '')) WHEN phone_number REGEXP '^[6-9][0-9]{9}$' THEN CONCAT('+91', REGEXP_REPLACE(phone_number, '[^0-9]', '')) ELSE REGEXP_REPLACE(phone_number, '[^0-9]', '') END AS standardized_phone FROM customers WHERE phone_number IS NOT NULL; -- Clean product codes and standardize format SELECT product_id, product_code AS original_code, UPPER(REGEXP_REPLACE(product_code, '[^A-Za-z0-9]', '')) AS clean_code, CASE WHEN product_code REGEXP '^[A-Za-z]{2,3}[0-9]{3,6}$' THEN CONCAT( UPPER(REGEXP_SUBSTR(product_code, '^[A-Za-z]+')), '-', REGEXP_SUBSTR(product_code, '[0-9]+$') ) ELSE UPPER(REGEXP_REPLACE(product_code, '[^A-Za-z0-9]', '')) END AS standardized_code FROM products WHERE product_code IS NOT NULL; -- Remove extra spaces and standardize names SELECT customer_id, customer_name AS original_name, TRIM(REGEXP_REPLACE(customer_name, '[[:space:]]+', ' ')) AS clean_name, REGEXP_REPLACE( TRIM(REGEXP_REPLACE(customer_name, '[[:space:]]+', ' ')), '^([a-z])', UPPER('\\1') ) AS formatted_name FROM customers WHERE customer_name IS NOT NULL AND customer_name REGEXP '[[:space:]]{2,}|^[a-z]';
Line-by-line Tamil Explanation:
• REGEXP_REPLACE(phone_number, '[^0-9+]', '') - Phone number la digits aur + sign except ella characters ah remove panrom
• '[^0-9+]' - Numbers aur + sign allama other characters ah match panrum
• WHEN phone_number REGEXP '^\+91' - +91 la start agura numbers identify panrom
• CONCAT('+91', REGEXP_REPLACE(phone_number, '[^0-9]', '')) - Indian country code add panni standardize panrom
• UPPER(REGEXP_REPLACE(product_code, '[^A-Za-z0-9]', '')) - Product code la special characters remove panni uppercase panrom
• REGEXP_SUBSTR(product_code, '^[A-Za-z]+') - Product code start la irukra letters ah extract panrom
• REGEXP_SUBSTR(product_code, '[0-9]+$') - Product code end la irukra numbers ah extract panrom
• TRIM(REGEXP_REPLACE(customer_name, '[[:space:]]+', ' ')) - Multiple spaces ah single space ah replace panrom
• '[[:space:]]+' - One or more whitespace characters ah match panrum
• Data Quality: Inconsistent formats ah uniform ah convert panalam
• Database Integrity: Clean data storage, efficient searching

4. Advanced Pattern Matching - Complex business validation

-- PAN card validation (Indian tax identification) SELECT customer_id, pan_number, CASE WHEN pan_number REGEXP '^[A-Z]{5}[0-9]{4}[A-Z]{1}$' THEN 'Valid PAN Format' ELSE 'Invalid PAN Format' END AS pan_status, REGEXP_SUBSTR(pan_number, '^[A-Z]{3}', 1, 1) AS pan_series, REGEXP_SUBSTR(pan_number, '[A-Z]{2}', 1, 2) AS name_initials FROM customers WHERE pan_number IS NOT NULL; -- Aadhar number validation (Indian unique ID) SELECT customer_id, aadhar_number, CASE WHEN aadhar_number REGEXP '^[2-9][0-9]{3}[[:space:]][0-9]{4}[[:space:]][0-9]{4}$' THEN 'Valid Aadhar Format' WHEN aadhar_number REGEXP '^[2-9][0-9]{11}$' THEN 'Valid Aadhar (No Spaces)' ELSE 'Invalid Aadhar' END AS aadhar_status, REGEXP_REPLACE(aadhar_number, '[^0-9]', '') AS aadhar_digits_only FROM customers WHERE aadhar_number IS NOT NULL; -- Credit card validation (basic format check) SELECT payment_id, card_number, CASE WHEN card_number REGEXP '^4[0-9]{15}$' THEN 'Visa Card' WHEN card_number REGEXP '^5[1-5][0-9]{14}$' THEN 'MasterCard' WHEN card_number REGEXP '^3[47][0-9]{13}$' THEN 'American Express' WHEN card_number REGEXP '^6(?:011|5[0-9]{2})[0-9]{12}$' THEN 'Discover Card' ELSE 'Unknown Card Type' END AS card_type, REGEXP_REPLACE(card_number, '([0-9]{4})([0-9]{4})([0-9]{4})([0-9]{4})', '\\1-\\2-\\3-\\4') AS formatted_card_number FROM payment_methods WHERE card_number IS NOT NULL AND payment_type = 'CREDIT_CARD'; -- GST number validation (Indian business tax ID) SELECT business_id, gst_number, CASE WHEN gst_number REGEXP '^[0-9]{2}[A-Z]{5}[0-9]{4}[A-Z]{1}[1-9A-Z]{1}[Z]{1}[0-9A-Z]{1}$' THEN 'Valid GST Format' ELSE 'Invalid GST Format' END AS gst_status, REGEXP_SUBSTR(gst_number, '^[0-9]{2}', 1, 1) AS state_code, REGEXP_SUBSTR(gst_number, '[A-Z]{5}[0-9]{4}[A-Z]', 1, 1) AS pan_section FROM businesses WHERE gst_number IS NOT NULL;
Line-by-line Tamil Explanation:
• pan_number REGEXP '^[A-Z]{5}[0-9]{4}[A-Z]{1}$' - PAN card format validation (5 letters, 4 numbers, 1 letter)
• '^[A-Z]{5}' - Start la exactly 5 uppercase letters venum
• '[0-9]{4}' - Aduth
