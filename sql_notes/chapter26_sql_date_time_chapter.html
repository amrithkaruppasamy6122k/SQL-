📖 Definition (Date Time Functions Enna Solluranga?)

Date and Time Functions na MySQL la temporal data (time-related data) ah manipulate panna, format panna, calculate panna use agura built-in functions collection thaan. Idhu business applications la romba mukkiyam - payroll, billing, analytics, reporting ellame date-time operations mela depend aagum!

Date Time Functions oda powerful capabilities:

  • Date Extraction: Year, month, day, hour, minute, second ah separate ah extract panna mudiyum
  • Date Arithmetic: Dates kulla add/subtract operations perform panna mudiyum
  • Format Conversion: Different date formats ku convert panna mudiyum
  • Business Logic: Working days, age calculation, tenure calculation lam easy
  • Timezone Handling: Different timezone data ah handle panna mudiyum
  • Period Calculations: Duration, intervals, date differences calculate panalam

🕒 MySQL Date Time Data Types:

  • DATE: 'YYYY-MM-DD' format (1000-01-01 to 9999-12-31)
  • TIME: 'HH:MM:SS' format (-838:59:59 to 838:59:59)
  • DATETIME: 'YYYY-MM-DD HH:MM:SS' format
  • TIMESTAMP: Unix timestamp with timezone awareness
  • YEAR: 4-digit year values (1901 to 2155)

⚠️ Date Time la Jaakkiradhaga Irukanume:

  • Timezone Issues: Server timezone aur client timezone different aana confusion varum
  • Date Format: Input format wrong aana implicit conversion try aagum
  • Null Values: Date calculations la NULL values unexpected results kudukum
  • Performance: Date functions WHERE clause la use pannumpothu index utilization slow aagum
  • Business Rules: Leap years, month-end dates, weekend calculations careful ah handle pananum

-- Working days calculation (excluding weekends) SELECT employee_id, leave_start_date, leave_end_date, DATEDIFF(leave_end_date, leave_start_date) + 1 AS total_days, (DATEDIFF(leave_end_date, leave_start_date) + 1) - ( (WEEK(leave_end_date) - WEEK(leave_start_date)) * 2 + CASE WHEN DAYOFWEEK(leave_start_date) = 1 THEN 1 ELSE 0 END + CASE WHEN DAYOFWEEK(leave_end_date) = 7 THEN 1 ELSE 0 END ) AS working_days_approximate, CASE WHEN DAYOFWEEK(leave_start_date) IN (1, 7) OR DAYOFWEEK(leave_end_date) IN (1, 7) THEN 'Includes Weekend' ELSE 'Weekdays Only' END AS weekend_status FROM employee_leaves WHERE leave_status = 'APPROVED' AND leave_start_date >= DATE_SUB(CURDATE(), INTERVAL 3 MONTH); -- Age calculation with precision SELECT customer_name, birth_date, CURDATE() AS current_date, TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) AS age_years, TIMESTAMPDIFF(MONTH, birth_date, CURDATE()) AS age_months, TIMESTAMPDIFF(DAY, birth_date, CURDATE()) AS age_days, CASE WHEN TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) >= 60 THEN 'Senior Citizen' WHEN TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) >= 18 THEN 'Adult' ELSE 'Minor' END AS age_category, DATE_ADD(birth_date, INTERVAL (TIMESTAMPDIFF(YEAR, birth_date, CURDATE()) + 1) YEAR) AS next_birthday FROM customers WHERE birth_date IS NOT NULL ORDER BY age_years DESC LIMIT 20; -- Financial year and quarter calculations SELECT transaction_date, transaction_amount, CASE WHEN MONTH(transaction_date) >= 4 THEN YEAR(transaction_date) ELSE YEAR(transaction_date) - 1 END AS financial_year, CASE WHEN MONTH(transaction_date) IN (4, 5, 6) THEN 'Q1' WHEN MONTH(transaction_date) IN (7, 8, 9) THEN 'Q2' WHEN MONTH(transaction_date) IN (10, 11, 12) THEN 'Q3' ELSE 'Q4' END AS financial_quarter, LAST_DAY(transaction_date) AS month_end_date, DAY(LAST_DAY(transaction_date)) AS days_in_month FROM financial_transactions WHERE transaction_date >= '2024-01-01' ORDER BY transaction_date DESC LIMIT 15;

1. Payroll System - Employee Salary Calculations

Situation: Monthly payroll process pannum bodhu attendance, working days, overtime calculations accurate ah pananum

-- Monthly payroll calculation with date functions SELECT e.employee_id, e.employee_name, e.basic_salary, YEAR(CURDATE()) AS payroll_year, MONTH(CURDATE()) AS payroll_month, MONTHNAME(CURDATE()) AS payroll_month_name, -- Working days in current month DAY(LAST_DAY(CURDATE())) - ( SELECT COUNT(*) FROM calendar_dates cd WHERE cd.date_value BETWEEN DATE_FORMAT(CURDATE(), '%Y-%m-01') AND LAST_DAY(CURDATE()) AND DAYOFWEEK(cd.date_value) IN (1, 7) ) AS working_days_in_month, -- Employee actual working days COALESCE( ( SELECT COUNT(DISTINCT attendance_date) FROM attendance a WHERE a.employee_id = e.employee_id AND a.attendance_date >= DATE_FORMAT(CURDATE(), '%Y-%m-01') AND a.attendance_date <= LAST_DAY(CURDATE()) AND a.status = 'PRESENT' ), 0 ) AS days_worked, -- Leave days taken COALESCE( ( SELECT SUM(DATEDIFF(leave_end_date, leave_start_date) + 1) FROM leaves l WHERE l.employee_id = e.employee_id AND l.leave_start_date >= DATE_FORMAT(CURDATE(), '%Y-%m-01') AND l.leave_end_date <= LAST_DAY(CURDATE()) AND l.status = 'APPROVED' ), 0 ) AS leave_days, -- Calculate proportional salary ROUND( (e.basic_salary / DAY(LAST_DAY(CURDATE()))) * COALESCE( ( SELECT COUNT(DISTINCT attendance_date) FROM attendance a WHERE a.employee_id = e.employee_id AND a.attendance_date >= DATE_FORMAT(CURDATE(), '%Y-%m-01') AND a.attendance_date <= LAST_DAY(CURDATE()) AND a.status = 'PRESENT' ), 0 ), 2 ) AS calculated_salary FROM employees e WHERE e.status = 'ACTIVE' ORDER BY e.employee_id;

Tremendous Faayda:

  • Accurate Payroll: Working days based ah exact salary calculation
  • Leave Integration: Approved leaves automatic ah deduct aagum
  • Monthly Automation: Every month consistent payroll generation
  • Compliance: Labor law requirements meet pannum

2. E-commerce Order Management - Delivery Timeline Tracking

Situation: Customer orders ku delivery promises, SLA tracking, return period calculations pananum

-- Order delivery timeline management SELECT o.order_id, o.customer_id, o.order_date, o.order_time, -- Expected delivery calculation CASE WHEN o.delivery_type = 'EXPRESS' THEN DATE_ADD(o.order_date, INTERVAL 1 DAY) WHEN o.delivery_type = 'STANDARD' THEN DATE_ADD(o.order_date, INTERVAL 3 DAY) WHEN o.delivery_type = 'ECONOMY' THEN DATE_ADD(o.order_date, INTERVAL 7 DAY) ELSE DATE_ADD(o.order_date, INTERVAL 5 DAY) END AS expected_delivery_date, -- Actual delivery tracking o.delivered_date, CASE WHEN o.delivered_date IS NOT NULL THEN DATEDIFF(o.delivered_date, o.order_date) ELSE DATEDIFF(CURDATE(), o.order_date) END AS delivery_days_taken, -- SLA compliance check CASE WHEN o.delivered_date IS NULL AND CURDATE() > (CASE WHEN o.delivery_type = 'EXPRESS' THEN DATE_ADD(o.order_date, INTERVAL 1 DAY) WHEN o.delivery_type = 'STANDARD' THEN DATE_ADD(o.order_date, INTERVAL 3 DAY) WHEN o.delivery_type = 'ECONOMY' THEN DATE_ADD(o.order_date, INTERVAL 7 DAY) ELSE DATE_ADD(o.order_date, INTERVAL 5 DAY) END) THEN 'DELAYED' WHEN o.delivered_date IS NOT NULL AND o.delivered_date <= (CASE WHEN o.delivery_type = 'EXPRESS' THEN DATE_ADD(o.order_date, INTERVAL 1 DAY) WHEN o.delivery_type = 'STANDARD' THEN DATE_ADD(o.order_date, INTERVAL 3 DAY) WHEN o.delivery_type = 'ECONOMY' THEN DATE_ADD(o.order_date, INTERVAL 7 DAY) ELSE DATE_ADD(o.order_date, INTERVAL 5 DAY) END) THEN 'ON_TIME' WHEN o.delivered_date IS NOT NULL THEN 'LATE_DELIVERY' ELSE 'IN_TRANSIT' END AS delivery_status, -- Return period calculation CASE WHEN o.delivered_date IS NOT NULL THEN DATE_ADD(o.delivered_date, INTERVAL 7 DAY) ELSE NULL END AS return_deadline, -- Customer notification timing CASE WHEN o.delivered_date IS NULL AND DATEDIFF(CURDATE(), o.order_date) >= 2 THEN 'SEND_UPDATE' ELSE 'NO_ACTION' END AS notification_required FROM orders o WHERE o.order_date >= DATE_SUB(CURDATE(), INTERVAL 30 DAY) ORDER BY o.order_date DESC;

3. Banking Loan Management - EMI and Interest Calculations

Situation: Bank la customer loans ku EMI schedule, interest calculations, penalty calculations pananum

-- Comprehensive loan management system SELECT l.loan_id, l.customer_id, l.loan_amount, l.interest_rate, l.loan_start_date, l.tenure_months, -- Loan end date calculation DATE_ADD(l.loan_start_date, INTERVAL l.tenure_months MONTH) AS loan_end_date, -- Next EMI due date ( SELECT MIN(due_date) FROM emi_schedule es WHERE es.loan_id = l.loan_id AND es.due_date > CURDATE() AND es.status = 'PENDING' ) AS next_emi_date, -- Overdue EMI check ( SELECT COUNT(*) FROM emi_schedule es WHERE es.loan_id = l.loan_id AND es.due_date < CURDATE() AND es.status = 'PENDING' ) AS overdue_emis, -- Days overdue for penalty calculation CASE WHEN ( SELECT MIN(due_date) FROM emi_schedule es WHERE es.loan_id = l.loan_id AND es.due_date < CURDATE() AND es.status = 'PENDING' ) IS NOT NULL THEN DATEDIFF( CURDATE(), ( SELECT MIN(due_date) FROM emi_schedule es WHERE es.loan_id = l.loan_id AND es.due_date < CURDATE() AND es.status = 'PENDING' ) ) ELSE 0 END AS days_overdue, -- Penalty calculation CASE WHEN ( SELECT COUNT(*) FROM emi_schedule es WHERE es.loan_id = l.loan_id AND es.due_date < CURDATE() AND es.status = 'PENDING' ) > 0 THEN ROUND( (l.loan_amount * 0.02 / 100) * DATEDIFF( CURDATE(), ( SELECT MIN(due_date) FROM emi_schedule es WHERE es.loan_id = l.loan_id AND es.due_date < CURDATE() AND es.status = 'PENDING' ) ), 2 ) ELSE 0 END AS penalty_amount, -- Loan completion percentage ROUND( (TIMESTAMPDIFF(MONTH, l.loan_start_date, CURDATE()) * 100.0) / l.tenure_months, 2 ) AS completion_percentage, -- Remaining tenure CASE WHEN CURDATE() < DATE_ADD(l.loan_start_date, INTERVAL l.tenure_months MONTH) THEN TIMESTAMPDIFF( MONTH, CURDATE(), DATE_ADD(l.loan_start_date, INTERVAL l.tenure_months MONTH) ) ELSE 0 END AS remaining_months FROM loans l WHERE l.status = 'ACTIVE' AND l.loan_start_date <= CURDATE() ORDER BY days_overdue DESC, next_emi_date;

-- Healthcare appointment and medication management SELECT p.patient_id, p.patient_name, p.birth_date, -- Patient age calculation TIMESTAMPDIFF(YEAR, p.birth_date, CURDATE()) AS patient_age, -- Age category for pediatric/geriatric care CASE WHEN TIMESTAMPDIFF(YEAR, p.birth_date, CURDATE()) < 18 THEN 'Pediatric' WHEN TIMESTAMPDIFF(YEAR, p.birth_date, CURDATE()) >= 65 THEN 'Geriatric' ELSE 'Adult' END AS age_category, -- Last appointment tracking ( SELECT MAX(appointment_date) FROM appointments a WHERE a.patient_id = p.patient_id AND a.status = 'COMPLETED' ) AS last_appointment_date, -- Days since last visit CASE WHEN ( SELECT MAX(appointment_date) FROM appointments a WHERE a.patient_id = p.patient_id AND a.status = 'COMPLETED' ) IS NOT NULL THEN DATEDIFF( CURDATE(), ( SELECT MAX(appointment_date) FROM appointments a WHERE a.patient_id = p.patient_id AND a.status = 'COMPLETED' ) ) ELSE NULL END AS days_since_last_visit, -- Next scheduled appointment ( SELECT MIN(appointment_date) FROM appointments a WHERE a.patient_id = p.patient_id AND a.appointment_date > CURDATE() AND a.status = 'SCHEDULED' ) AS next_appointment_date, -- Follow-up reminder check CASE WHEN ( SELECT MAX(appointment_date) FROM appointments a WHERE a.patient_id = p.patient_id AND a.status = 'COMPLETED' ) IS NOT NULL AND DATEDIFF( CURDATE(), ( SELECT MAX(appointment_date) FROM appointments a WHERE a.patient_id = p.patient_id AND a.status = 'COMPLETED' ) ) >= 90 AND ( SELECT COUNT(*) FROM appointments a WHERE a.patient_id = p.patient_id AND a.appointment_date > CURDATE() AND a.status = 'SCHEDULED' ) = 0 THEN 'FOLLOW_UP_NEEDED' ELSE 'NO_ACTION' END AS follow_up_status, -- Birthday reminder for wellness check CASE WHEN DATE_FORMAT(p.birth_date, '%m-%d') = DATE_FORMAT(DATE_ADD(CURDATE(), INTERVAL 30 DAY), '%m-%d') THEN 'BIRTHDAY_WELLNESS_CHECK' ELSE 'NO_REMINDER' END AS birthday_wellness_reminder FROM patients p WHERE p.status = 'ACTIVE' ORDER BY days_since_last_visit DESC NULLS LAST; -- Medication reminder system SELECT pr.prescription_id, pr.patient_id, p.patient_name, pr.medicine_name, pr.dosage, pr.frequency_per_day, pr.start_date, pr.duration_days, DATE_ADD(pr.start_date, INTERVAL pr.duration_days DAY) AS end_date, -- Medication adherence tracking DATEDIFF(CURDATE(), pr.start_date) AS days_elapsed, pr.duration_days - DATEDIFF(CURDATE(), pr.start_date) AS days_remaining, -- Reminder status CASE WHEN CURDATE() < pr.start_date THEN 'NOT_STARTED' WHEN CURDATE() > DATE_ADD(pr.start_date, INTERVAL pr.duration_days DAY) THEN 'COMPLETED' WHEN DATE_ADD(pr.start_date, INTERVAL pr.duration_days DAY) <= DATE_ADD(CURDATE(), INTERVAL 3 DAY) THEN 'ENDING_SOON' ELSE 'ACTIVE' END AS medication_status, -- Refill reminder CASE WHEN pr.duration_days - DATEDIFF(CURDATE(), pr.start_date) <= 7 AND pr.duration_days - DATEDIFF(CURDATE(), pr.start_date) > 0 THEN 'REFILL_REMINDER' ELSE 'NO_REMINDER' END AS refill_status FROM prescriptions pr JOIN patients p ON pr.patient_id = p.patient_id WHERE pr.start_date <= CURDATE() AND DATE_ADD(pr.start_date, INTERVAL pr.duration_days DAY) >= CURDATE() ORDER BY days_remaining;

INTERVAL 1 MONTH), '%Y-%m-') || LPAD(DAY(s.start_date), 2, '0') END WHEN s.billing_cycle = 'ANNUAL' THEN CASE WHEN DATE_FORMAT(s.start_date, '%m-%d') <= DATE_FORMAT(CURDATE(), '%m-%d') THEN CONCAT(YEAR(CURDATE()), '-', DATE_FORMAT(s.start_date, '%m-%d')) ELSE CONCAT(YEAR(CURDATE()) - 1, '-', DATE_FORMAT(s.start_date, '%m-%d')) END END AS current_billing_start, -- Next billing date CASE WHEN s.billing_cycle = 'MONTHLY' THEN CASE WHEN DAY(s.start_date) <= DAY(CURDATE()) THEN DATE_ADD( STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ), INTERVAL 1 MONTH ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ) END WHEN s.billing_cycle = 'ANNUAL' THEN CASE WHEN DATE_FORMAT(s.start_date, '%m-%d') <= DATE_FORMAT(CURDATE(), '%m-%d') THEN STR_TO_DATE( CONCAT(YEAR(CURDATE()) + 1, '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) END END AS next_billing_date, -- Days until next billing DATEDIFF( CASE WHEN s.billing_cycle = 'MONTHLY' THEN CASE WHEN DAY(s.start_date) <= DAY(CURDATE()) THEN DATE_ADD( STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ), INTERVAL 1 MONTH ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ) END WHEN s.billing_cycle = 'ANNUAL' THEN CASE WHEN DATE_FORMAT(s.start_date, '%m-%d') <= DATE_FORMAT(CURDATE(), '%m-%d') THEN STR_TO_DATE( CONCAT(YEAR(CURDATE()) + 1, '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) END END, CURDATE() ) AS days_to_next_billing, -- Subscription age TIMESTAMPDIFF(MONTH, s.start_date, CURDATE()) AS subscription_age_months, -- Trial period check CASE WHEN s.trial_days > 0 AND DATEDIFF(CURDATE(), s.start_date) <= s.trial_days THEN 'TRIAL_ACTIVE' WHEN s.trial_days > 0 AND DATEDIFF(CURDATE(), s.start_date) > s.trial_days THEN 'TRIAL_ENDED' ELSE 'NO_TRIAL' END AS trial_status, -- Payment reminder logic CASE WHEN DATEDIFF( CASE WHEN s.billing_cycle = 'MONTHLY' THEN CASE WHEN DAY(s.start_date) <= DAY(CURDATE()) THEN DATE_ADD( STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ), INTERVAL 1 MONTH ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ) END ELSE CASE WHEN DATE_FORMAT(s.start_date, '%m-%d') <= DATE_FORMAT(CURDATE(), '%m-%d') THEN STR_TO_DATE( CONCAT(YEAR(CURDATE()) + 1, '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) END END, CURDATE() ) <= 7 THEN 'RENEWAL_REMINDER' WHEN DATEDIFF( CASE WHEN s.billing_cycle = 'MONTHLY' THEN CASE WHEN DAY(s.start_date) <= DAY(CURDATE()) THEN DATE_ADD( STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ), INTERVAL 1 MONTH ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', MONTH(CURDATE()), '-', DAY(s.start_date)), '%Y-%m-%d' ) END ELSE CASE WHEN DATE_FORMAT(s.start_date, '%m-%d') <= DATE_FORMAT(CURDATE(), '%m-%d') THEN STR_TO_DATE( CONCAT(YEAR(CURDATE()) + 1, '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) ELSE STR_TO_DATE( CONCAT(YEAR(CURDATE()), '-', DATE_FORMAT(s.start_date, '%m-%d')), '%Y-%m-%d' ) END END, CURDATE() ) < 0 THEN 'OVERDUE' ELSE 'ACTIVE' END AS billing_status FROM subscriptions s JOIN customers c ON s.customer_id = c.customer_id WHERE s.status = 'ACTIVE' ORDER BY days_to_next_billing;
